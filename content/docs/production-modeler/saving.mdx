Work is kept as you go. A local draft is written when the model is saved, either
by you or by autosave, and a signed in account also keeps the model in the cloud
with a revision number. A card on the overview says when its draft was last
written, in the words you would use, with the exact time on hover.

The overview searches both shelves at once by name and reads them in whichever
order you pick: by name, biggest first, or by what changed last. A model can be
copied there as well, which is how a variant starts without exporting and
importing it again. Inside a model, the history button beside the trail switches
to the models you had open last, so comparing two of them no longer goes through
the overview.

Saving the settings dialog writes the model out the same way, so a solver mode
or a grid you change there survives a reload. A model you are only allowed to
read says so at the top of that dialog and keeps its settings unchanged.

Leaving with unsaved changes asks first, whether you close the tab or follow a
link out of the modeler. When following a link or closing the desktop window,
choose Save and close to save before leaving. The dialog stays open while saving
and shows an error if saving fails, so you can retry or keep editing. Closing a
browser tab uses the browser's own warning; save your model before closing it.

## Conflicts and recovery

If the same model was changed somewhere else, the modeler does not silently
overwrite anything. It shows your version, the version you started from, and the
remote version, and you decide.

After an interrupted session the modeler offers what it recovered on the next
visit rather than dropping it.

## Snapshots

A snapshot is a named point you can come back to. Restore one and it becomes a
new revision of the model, so restoring never destroys what you had.

## Sharing

Publishing a model creates a read only link. Anyone with it can look at the
shared revision and clone it into their own account, and their clone is
independent of yours.

A model built with mods says so while you share it, and again on its card in
Browse. Whoever opens it without those mods would otherwise see a broken factory
and no reason for it.

Everything published this way is also listed under Browse, which you can reach
from the modeler start page without an account. A card there says what the model
delivers, what it has to be fed, which buildings it is made of, and how large it
is, so you can tell models apart before opening one. You can search by name,
filter by tag, and order by newest or by name. Copying one into your own models
needs an account, opening one does not.

A model built against older game data is marked as such. It still opens, and
your copy is migrated when you edit it.

## Game data profiles

Game-data imports and profiles are available only in the desktop app. The browser
uses managed SF+ data and links to the desktop download.

The desktop app starts with one SF+ profile. While that profile is unchanged,
it uses current SF+ data from the web when you are online and the copy bundled
with the app when you are offline.

The model overview opens with your game data collection. Choose **Ready to plan**
on Satisfactory+ to start with the included data, or **Import .kdata** on Vanilla
or Your modpack to choose a file made by [KModelerExporter](https://ficsit.app/mod/KModelerExporter)
in your game. Those two
cards are import shortcuts; they do not include another game's recipes.

To generate your game data, install KModelerExporter with the mods you want to
use, then load a save. Open the in-game chat and run `/modeler-generate`. The
export is saved as `FactoryGame/KMods/ModelerExport/ProductionModeler.kdata`
inside your Satisfactory installation folder. Import that file in the desktop
app. Run the command again and import a new export after changing your modpack.

The import shows the selected file and the number of items, buildings and recipes
after checking it. Give the profile a name and create it. Your previous profiles
and saved models stay in place. The imported profile appears in the collection
and becomes active. You can also drag a `.kdata` file onto the overview or editor.
Unsaved editor changes must be handled before activating new game data.

You can keep separate, switchable profiles for Vanilla and each modpack in the
desktop app. The new-model page shows the active game data and lets you change
it before creating a model. Keep the `.kdata` file as a backup. Desktop profiles
also retain their exported images. Imported profiles are not replaced with web data.

To replace a profile, expand **Replace an existing profile instead** in the import
preview, check the named target and confirm. This also lets you override SF+ locally.
Reset that profile in Settings to return to managed SF+ data. Advanced desktop
storage, profile renaming, deletion, export and refresh remain in **Desktop data**.

Your saved models are below the game data collection. Use **Your models** at the
top to jump there, search by name, or choose **Import file** for a portable model.
Local models remain usable while cloud models load. A cloud or public-list error
offers a retry and does not replace your local models with an empty screen.

## Import and export

Models can be exported and imported as `.sfmd`, the desktop Satisfactory Modeler
format. An import previews what it found before anything is created, including
whatever it could not represent, so a file is never partially applied without
saying so.

Where a model cannot be expressed in the legacy format, the modeler exports its
own versioned format instead of dropping detail quietly.

Choose Import Planner data on the model overview to bring over your local plan
and saved cloud plans. Cloud imports load each complete plan, including its
nodes and connections. Parallel flows carrying the same material between the
same ports become one connection with their combined rate. The original Planner
data stays unchanged.

If an earlier import created an empty cloud model, run Import Planner data again.
The complete plan becomes a new model without overwriting the empty copy or any
edits you made to it. Successfully imported revisions are skipped on later runs.
If the original plan has no nodes, open it in the Planner, calculate and save it,
then retry. An empty or unreadable source is reported as a failed import instead
of being saved as an empty model.

## Catalog versions

Every model records the catalog it was built against. When the game data behind
the modeler is updated, existing models stay on their own catalog until you
migrate them, and the migration is previewed first.

The versions in play are listed in the help dialog, which also copies them for a
bug report.
