New models start locally, even when you are signed in.
Use **Save** in the toolbar to keep your work.

- Autosave is on by default, with a five-minute cooldown from the first unsaved edit.
- Further edits do not restart the countdown, so continuous editing still gets saved.
- Change **Autosave cooldown in minutes** and the backup limit in **Settings**, then
  **Saves and recovery**. The minimum cooldown is one minute.
- Manual saves work immediately. After a save, any remaining changes wait for a
  fresh cooldown. Unchanged models do not trigger automatic writes or notifications.
- A toast confirms each completed model save and says whether it was saved locally
  or to the cloud. Desktop saves waiting for cloud sync are reported as local saves.

Autosave pauses during loading, game-data switches, and other model operations.
It does not save read-only models or retry unresolved cloud conflicts. Other
failed saves remain retryable after a full cooldown. Leaving the workspace
cancels a pending autosave; save first if you want to keep unsaved changes.

Browser models and backups stay in that browser's site storage.
Clearing site data can remove them and your imported game-data profiles.
Keep important exports outside the browser.

Desktop models are `.ksfmd` files.
Find their folder under **Settings**, then **Desktop data**.
Recovery backups stay in app storage, not the model folder.
Before using **Reload data** after external file edits, save or discard open model changes.
That action reloads the page and discards unsaved settings.

To save to your account, sign in and enable the cloud button in the model header.
Later saves update the cloud model; the button cannot make it local-only again.
The cloud button stays visible on editable models. When unavailable, its tooltip
explains whether you need to sign in on the current site or are using imported
browser game data. Localhost follows the same rules as the published site.

:::caution[Imported browser packs stay local]
Models using browser-imported `.kdata` profiles cannot be cloud-saved.
After switching a cloud model to one, choose **Save a local copy** to keep your edits.
The cloud original stays unchanged.
:::

Leaving with unsaved changes offers three choices:

- **Save and close** saves first, then leaves.
- **Keep editing** cancels leaving without saving.
- **Leave anyway** drops unsaved changes without creating a recovery copy.

If saving fails or changes remain unsaved, the model stays open.
Desktop window closing uses the same choices.
Browser tab closing or reloading uses the browser's own warning, with no save action.
Cancel that warning and save in the Modeler before closing.

## Conflicts and recovery

A browser **Save conflict** compares the base, local, and cloud versions.

- **Keep local copy** saves your work as a separate private local model.
- **Use cloud version** replaces your open work with the remote model.

Browser cloud saves write a recovery draft before uploading.
If upload fails, check **Messages** and retry when connected.
A recovery draft is not a cloud save or a queued desktop-style upload.

Desktop saves locally first and can queue cloud updates while offline.
**Saved locally** does not mean **Synced to cloud**.
Resolve pending sync, sign-in, error, or conflict states before relying on another device.
Desktop sync snapshots the remote version as **Desktop auto-sync**, then uploads the local model.
This can replace edits from another session, so avoid editing on several devices at once.
A failed snapshot or upload leaves sync pending or in an error/conflict state.
Cloud storage accepts valid models whose older or local game-data version is
unavailable on the server. Saving preserves that binding. Keep the matching
`.kdata` pack for another device; cloud saving does not upload the pack or make
its recipes available to server calculations.

When **Recover local draft** appears, compare the draft with the open model.
Choose **Restore draft**, inspect the result, then save.
**Discard draft** removes the recovery draft and reloads the cloud version.
Recovery cannot restore changes that were never saved.

## Snapshots

Open **Snapshots** with the camera button in the model header.

- Local backups are created on draft saves.
- **Maximum backups** defaults to 100 per model; older entries are pruned.
- Set it to zero to stop retaining backups.
- Restore a backup under **Recover local draft**, then inspect and save the replaced graph.

1. For a cloud snapshot, sign in as the model's owner and finish its cloud save.
2. Enter a name and choose **Create snapshot**.
3. To restore, choose the snapshot's restore action and confirm.

Cloud snapshot actions need a connection; queued desktop saves are not enough.
Restoration also needs the snapshot's game data.
Restoring writes a new revision, but does not automatically snapshot the state it replaces.
Create a snapshot or export first if you may want that state back.
Deleting a named snapshot is permanent.

## Sharing

1. Sign in and open a model you own.
2. Open **Share model** and enable **Publish a viewing link**.
3. Wait for the cloud save and publication, then choose **Copy link**.

Publishing a local model requests cloud saving too.
Anyone can view a public model without an account; only its owner can edit it.
The link is not a frozen snapshot: later cloud saves can change what readers see.
Turn off publication to make it private again.
Copies already made by other people remain independent.

Public models also appear in **Browse**, with search and tag filters.
Inside a shared model, use **Edit a copy** instead of changing the original.
Signed-out users and users of browser-imported packs get a local copy.
Check mod notices and game-data warnings before trusting the results.
A viewing link does not install the required mods or pack.

## Game data profiles

Game-data imports and profiles are available only in the desktop app. The browser
uses managed SF+ data and links to the desktop download.

The desktop app starts with one SF+ profile. While that profile is unchanged,
it uses current SF+ data from the web when you are online and the copy bundled
with the app when you are offline.

The model overview opens with your game data collection. Choose **Ready to plan**
on Satisfactory+ to start with the included data, or **Import .kdata** on Vanilla
or Your modpack to choose a file made by [KModelerExporter](https://ficsit.app/mod/KModelerExporter)
in your game. Those two
cards are import shortcuts; they do not include another game's recipes.

To generate your game data, install KModelerExporter with the mods you want to
use, then load a save. Open the in-game chat and run `/modeler-generate`. The
export is saved as `FactoryGame/KMods/ModelerExport/ProductionModeler.kdata`
inside your Satisfactory installation folder. Import that file in the desktop
app. Run the command again and import a new export after changing your modpack.

The import shows the selected file and the number of items, buildings and recipes
after checking it. Give the profile a name and create it. Your previous profiles
and saved models stay in place. The imported profile appears in the collection
and becomes active. You can also drag a `.kdata` file onto the overview or editor.
Unsaved editor changes must be handled before activating new game data.

You can keep separate, switchable profiles for Vanilla and each modpack in the
desktop app. The new-model page shows the active game data and lets you change
it before creating a model. Keep the `.kdata` file as a backup. Desktop profiles
also retain their exported images. Imported profiles are not replaced with web data.

To replace a profile, expand **Replace an existing profile instead** in the import
preview, check the named target and confirm. This also lets you override SF+ locally.
Reset that profile in Settings to return to managed SF+ data. Advanced desktop
storage, profile renaming, deletion, export and refresh remain in **Desktop data**.

Your saved models are below the game data collection. Use **Your models** at the
top to jump there, search by name, or choose **Import file** for a portable model.
Local models remain usable while cloud models load. A cloud or public-list error
offers a retry and does not replace your local models with an empty screen.

## Import and export

1. Open **Import and export**, then choose **Export .ksfmd model**.
2. Keep the browser download, or choose a destination in the desktop save dialog.

`.ksfmd` contains the graph and model settings, including native Modeler details.
Older external readers may not preserve those details; check export **Messages**.
Exports exclude game data, images, recovery backups, undo history, and solver results.
Keep the matching `.kdata` file separately.

Imports accept `.ksfmd`, `.sfpmd`, and `.sfmd`, with a preview and a 5 MiB limit.
Follow [Importing](/production-modeler/importing/) for files, savegames, and Planner results.

Choose Import Planner data on the model overview to bring over your local plan
and saved cloud plans. Cloud imports load each complete plan, including its
nodes and connections. Parallel flows carrying the same material between the
same ports become one connection with their combined rate. The original Planner
data stays unchanged.

If an earlier import created an empty cloud model, run Import Planner data again.
The complete plan becomes a new model without overwriting the empty copy or any
edits you made to it. Successfully imported revisions are skipped on later runs.
If the original plan has no nodes, open it in the Planner, calculate and save it,
then retry. An empty or unreadable source is reported as a failed import instead
of being saved as an empty model.

## Catalog versions

Models record their game-data version, not a copy of the pack.
Open **Game data** in the header to switch or reload an installed pack on browser or desktop.
The graph, unsaved edits, and undo/redo history stay intact.
The model's data binding is stored on the next save, including autosave.
Switching data does not automatically migrate recipes or rewire connections.

If bound data is missing, **Using selected game data** marks the fallback.
Nodes and connections stay; missing references appear in **Messages**.
Results may differ, and the saved model stays unchanged until you save.
If neither saved nor selected data loads, editing and calculating are blocked.
For pack setup, switching, and migration details, see [Game data](/production-modeler/game-data/).
