Most buildings are an ordinary recipe: fixed inputs, fixed outputs, one machine.
Satisfactory Plus adds several that are not, and each one is modelled from what
the game data actually says.

## Refined Power

A boiler record names every building that has to cooperate, so a boiler and its
heater both become required roles on one node. You cannot place half an assembly.
Coolers and turbines stand alone.

The generator attached to a turbine converts its speed into electricity through
its power curve. Where the catalog includes the attachment, complete curve and
maximum output, the modeler uses that profile to calculate power. If a required
profile is missing or unsupported, the result stays unknown and the node explains
why. Material flow can still be calculated from the recipe.

## Slug Hatchery and Terrarium

Both produce only while they are comfortable. Temperature and humidity have to
sit inside the ranges of the slug you are hatching or breeding, and outside them
the building makes nothing at all. The environment gates production, it never
scales it, so inside the range the exported rates apply unchanged.

Without modules a hatchery sits at 25 degrees and 0.5 humidity. A new node
starts with values inside the selected slug's comfort ranges. Set these to the
readings your modules actually maintain. Explicit temperature and humidity
values stay unchanged when you calculate or reopen a saved model. A value
outside the comfort range produces an error for that connected group.

A hatchery in game also checks the time of day before it hatches, and the modeler
does not. The value that says which part of the day a slug wants comes out of the
export as a number that is not one of the states the game defines, so there is
nothing to check against. Read a hatchery rate as the rate while it is awake. A
terrarium is unaffected, because breeding never looks at the clock.

:::caution[Expected value is a lower bound]
Some slug outcomes raise their own chance after every failed cycle, so the chance
the game data lists is only where that outcome starts. A yellow slug listed at
5.6 percent is really worth about 20 percent over a long run. The modeler knows
how that works out, but the game data currently states these chances at a
precision that makes the exact answer too long to write down, so it keeps the
starting chance and understates them. It flags exactly which outputs this affects
rather than presenting a number that looks precise.
:::

## Farming plots

A plot offers one slot per module type: harvester, irrigation and greenhouse. A
recipe that requires a slot will not solve without it.

Only the greenhouse changes the rate. It runs the plot at 1.5 times its
potential, which speeds up the whole cycle, so a greenhouse plot consumes half
again as much seed and water as well as producing half again as much crop.

## Air Collector

An Air Collector produces from what it can reach. You set how many nodes or
pillars it scans and how many other collectors sit nearby, and the rate follows:
the scan count times the yield per hit, clamped to the record's own minimum and
maximum, divided by the crowding penalty, rounded down to steps of 500.

An unscanned collector still produces the minimum.

One variant works from build height instead of scanning. There you enter how
high the collector stands, and its base output scales from once to five times
across the range the buildable allows. Height is measured in centimetres and
can include a fractional part. For example, 8,817.5 cm with one nearby collector
yields 3,500 litres per six-second cycle, or 35 cubic metres per minute, for the
height-based air profile.

## Modular Miner

A modular miner is assembled from a head, optional boosters, and a waste or
fluid module. Which combinations are allowed, what they cost in power, and how
they change the extraction rate all come from the miner description for that
resource.

It is clocked like anything else, and the clock scales what the whole assembly
moves, the acid a fluid head drinks included. The range comes from the miner's
own building record, so it can be narrower than the one a factory building
offers.

## Dimensional Depot

Choose the upload tier in the inspector when the loaded catalog includes the
Dimensional Depot. The base tier uploads 15 items per minute. Research tiers
shorten the time per item, and the selected tier limits the calculated upload
flow. A port limit can further restrict it. If an imported catalog has no verified
uploader profile, the inspector reports that the tier selection is unavailable.

## Solar panels and wind turbines

These follow the world rather than a fuel, so they have no input to size them.
Instead the node carries a count, and the summary shows the range the export
describes.

A solar panel is exact at both ends. The game hands the exported night value and
the exported day value straight to the power grid, so the modeler can state both.
What it cannot state is the long run average, because the length of a day is not
part of the export.

A wind turbine is not modelled at all. Its output is capped against its exported
maximum multiplied by a session setting that players can change and that the
export does not contain, so any ceiling the modeler printed would be wrong. It
says the value is unknown instead. Two turbines standing close together also stop
producing entirely, which is a placement rule the modeler has no way to see.

## Building limits

Some buildings may only exist a limited number of times in a save. Where the data
says so, the machines section of the summary adds how many the model uses against
that limit and how many are left, and it marks the row in words once the model
goes past it.

The solve is not blocked. The modeler has no view of your world or your save, so
it can tell you that a model would need more of a building than the game allows,
but it will not decide for you that the model is wrong.
