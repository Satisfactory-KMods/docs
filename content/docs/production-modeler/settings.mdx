Open **Modeler settings** and use the side navigation, or the scrolling top row on small screens.
Switching sections keeps your draft; Save and Cancel stay in the footer.

- **This model:** Calculation, connection paths and snap grids travel with the saved model.
- **This device:** machine defaults, recovery settings, number formats and appearance stay local.
- The drag threshold is a device preference inside Connections and grids.
- Applying defaults to existing nodes changes the model, not just your device preferences.

- **Save:** applies staged changes and saves other unsaved canvas work too.
- Saving follows the model's existing local or cloud-saving choice.
- Device preferences are kept after the model save succeeds.
- **Not saved:** the dialog stays open with its draft ready to retry.
- Editing and closing are disabled while Save runs.
- **Cancel**, closing or Escape discards the draft, including staged grids and machine defaults.
- Language and theme previews revert, but earlier canvas edits remain untouched.
- Desktop file and game-data operations are immediate exceptions, not drafts.

Read-only models allow device preferences, not model settings or applying defaults to nodes.
For a shared model, use **Edit a copy** from [Saving and sharing](/production-modeler/saving/).

## Calculation

Choose a [Calculation mode](/production-modeler/#what-the-solver-does):

- **None:** leave calculated values blank.
- **Manual:** solve entered equalities.
- **Basic:** also apply limits and maximize flows.
- **Full:** also honor connection priority; the default for new models.



**Random recipe output** offers fixed outputs or statistical expected values.
Expected values are long-run averages, not guaranteed output every cycle.
Fixed outputs do not override recipes or nodes that explicitly require expected values.

Set **Game multipliers** to match your session:

- **Recipe input multiplier:** scales consumption, except recipes marked exempt.
- **Power multiplier:** scales building power use.
- **Space Elevator multiplier:** scales output of recipes flagged for it.
- All three require positive values and default to 1.

**Show invalid diagnostics** marks invalid values on the canvas.
**Show exact connection mismatches** marks solved port values that differ from their connections.

Hiding markers does not fix issues or remove them from [Messages](/production-modeler/panels/#messages).

## Connections and grids

- **Path style:** Curves, Direct or orthogonal 2D routing changes drawing, not wiring.
- **Drag threshold in pixels:** raise it to ignore small movements, lower it to start dragging sooner.
- The [building grid](/production-modeler/canvas/#grids) snaps nodes; the connection grid snaps waypoints.
- Each grid has separate horizontal and vertical spacing.
- Enabling a grid affects future movement after Save.

To align existing work:

1. Set the grid spacing.
2. Choose **Everything**, **Current container** or **Selected**.
3. Press **Apply node grid** or **Apply connection grid**.
4. Read the updated count, then Save to keep the staged changes.

- Selected means selected nodes for the node grid, selected connections for the connection grid.
- Apply works even with interactive snapping off.




## Machine defaults


1. Pick a machine group from the loaded catalog.
2. Set machine, transport capacity, limit, automatic rounding and per-minute display.
3. Save the preferences.

Existing nodes stay unchanged unless you use **Apply defaults**.
Choose Everything, Current container or Selected, then apply and Save.
Incompatible machines, clocks or transport capacities are skipped.
Check the updated and skipped counts, or **Nothing to update**.


Catalogs without supported groups show a notice instead of empty controls.
For one existing node, use the [Inspector](/production-modeler/panels/#inspector).

## Number formats

1. Choose **Where the format applies**, such as Machine count, Connection rate or Summary.
2. Select **Fraction** or **Decimal**.
3. Set Digits and choose Nearest, Up or Down for rounding.
4. Set tooltip formats separately, then Save.


Defaults use Decimal with Digits set to 2, and Fraction for tooltips.
Formats change display, not calculation.
Rounding the displayed machine count up is not the node's automatic-rounding setting.

## Saves and recovery

- **Save automatically:** enables autosave on this device.
- **Autosave cooldown in minutes:** defaults to 5, with a minimum of 1. The countdown
  starts with the first unsaved edit and does not restart as you keep working.
- **Maximum backups:** defaults to 100 retained recovery backups.
- Autosave is enabled by default but pauses while editing or saving is blocked.
- Manual saves bypass the cooldown. Remaining unsaved changes wait for a fresh
  cooldown after a save attempt finishes.
- Autosave follows the model's cloud-saving choice; signing in does not enable cloud saving.
- A toast confirms a completed save and distinguishes local storage from cloud storage.
  Clean models do not trigger automatic saves or duplicate notifications.


:::caution[Keep unsaved work open during a data lock]
Missing game data can lock the model, but leaving still warns about unsaved work.
A failed **Save and close** keeps the model open.
Choose **Keep editing**, restore usable data, then save the model.
Saving device preferences does not save a locked model.
:::

:::caution[Desktop operations are immediate]
**Desktop data** manages model folders, files and game-data profiles.
Cancel does not undo these operations.
Reloading model files requires saved or discarded model changes and confirmation.
Reloads discard unsaved settings drafts, so save the dialog first if you need them.
:::

For pack changes without replacing your open graph, use the header's **Game data** control.
The [game-data guide](/production-modeler/game-data/) covers pack switching and desktop maintenance.

## Appearance

- **Language:** English or Deutsch.
- **Theme:** Light or Dark.
- Both preview immediately and stay on this device after Save.
- Cancel or closing restores the previous appearance.
