Build a factory graph. Connect recipes and buildings. Calculate material flow,
machine counts, and power without giving up control of the layout.

The browser and desktop app share the same model format and calculation core.
Desktop also provides local calculation, file-based storage, and bundled
Satisfactory+ and Vanilla game data. This guide covers the 1.2.0 workflow;
changes are listed in the
[changelog](/production-modeler/changelog/).

The [desktop download page](https://k-mods.com/production-modeler/download)
shows the available builds and a feature tour. Local desktop planning needs no
account. If downloads cannot load, choose **Check again**.

## Drawing or planning

- **Empty model:** choose every recipe and connection yourself.
- **Automatic plan:** choose a target part and rate, then review a proposed chain.

A recipe node can represent several machines. Its constraints and connections
determine how many are needed. Automatic planning creates the same editable
nodes; it does not lock you into the proposed layout.

## Plan a chain automatically

Choose an automatic starting point in the creation wizard, or select
**Plan automatically (Exp)** in the canvas palette.

The optional first step accepts a Satisfactory `.sav` file. Its unlocked recipe
paths are matched exactly against the loaded catalog, and the resulting recipe
and production-machine filters stay with the model. They constrain the wizard,
later automatic plans, catalog-backed palette entries and machine choices. The
palette shows when this filter is active and lets you remove it.

Only the matched catalog IDs are saved. The save binary is processed in memory
and is not stored in the model or browser draft. In the web app it goes to the
public savegame analyzer; the desktop app parses it locally and can do so
offline.

1. Pick the output part and rate.
2. Review recipe choices and alternate recipes.
3. Choose whether to attach resource sources.
4. Apply the plan and check **Messages** for unresolved inputs or loops.

The target becomes a limit on the root output. The solver sizes the upstream
chain. One **Undo** removes the entire addition.

Planning uses the loaded catalog locally. It prefers extraction for mined
resources and avoids packaging loops as production steps. A wiki item or recipe
can prefill the target.

:::note[Experimental planning]
**Exp** applies to automatic recipe selection. Review the result: large or
cyclic chains can still need manual wiring.
:::

## The language you read it in

Part, machine and recipe names follow the language you picked for the site. The
modeler asks the service for the catalog in that language and swaps it out when
you switch, so nothing has to be reloaded by hand. The desktop app and an
imported game-data pack follow the same language, as long as the pack carries
its translations. Text the game data was never translated into stays English,
and so does a pack exported before translations existed.

## Your first model

<Steps>

1. Select a game-data pack on the Modeler home page. **Activate** stays on that
   page. **Ready to plan** opens model creation with the selected pack.

2. Confirm the data, name the model, and review its settings. Choose an empty or
   automatic starting point and finish the review step.

3. Double-click empty canvas to open the palette. Right-click works too.
   There is no separate **+ Add** toolbar button.

4. Search for a recipe or building and place it. Drag from an output port to a
   compatible input to connect two nodes.

5. Select a node to open the **Inspector** on desktop. On narrow screens, select
   the node and choose **Edit**. Set a fixed rate for a production target, or a
   capacity ceiling for an upper limit.

6. Check **Summary** and **Messages**. Use **Calculate** for an immediate solve.
   Calculate refreshes every connected group, including unchanged groups with
   a previous error. Automatic calculation reuses unchanged results.

7. Choose **Save**. Export a `.ksfmd` file for a portable backup.

</Steps>

Recipes without a known production rate, such as one-off Space Elevator phase
recipes, are kept for existing model references but are absent from the palette
and automatic planning. The modeler does not assign them a made-up cycle time.

The palette is a small panel you can drag out of the way, and it leaves the
canvas visible and usable underneath. It opens with the search field ready, so
you can type straight away. Results are a grid of tiles; the arrow keys move
through them in both directions and Enter places the highlighted one.


Palette search covers names, inputs, and outputs. Filters narrow results by
mod, machine tier, progression tier, and alternate recipes. Drop a dragged
connection on empty space to get compatible choices and connect the new node
automatically.

The header's **Game data** control switches installed packs without losing the
graph, unsaved edits, viewport, or undo/redo history. **Reload selected data**
rereads an edited pack. See [Game data](/production-modeler/game-data/) before
testing a different mod combination.

:::caution[Keep a backup]
Unsaved edits live only in the open model. Browser drafts can be lost when
browser data is cleared. Use **Save** and keep exported files for important work.
Signing in alone does not enable cloud saving.

The desktop home page shows the installed app version, commit, and build date.
When an update is available, a dialog links to the changelog and offers **Close**,
**Skip this version**, or installation. Closing reminds you at the next app
start. Skipping waits for a newer version. The update reminder on the home page
can reopen either choice, and the dialog shows download and installation progress.
Before installing from an open model, resolve any unsaved changes.
:::

## Reading a node

- **Left ports:** inputs. **Right ports:** outputs.
- **Solid rates:** items per minute. **Fluids and gases:** cubic metres per minute.
- **Header chevron:** inline controls. **Inspector:** the same node's detailed settings.
- **Limit badge:** an explicit constraint, not necessarily the calculated flow.
- **Unknown value:** unresolved, not zero.

Decimal display rounds exact values directly, including very large integers.
Changing the display precision never changes the calculation. If an exact result
is too long for the supported number format, the affected connected group shows
a calculation error. Independent groups still calculate normally.


Recipe nodes can show rates or machine counts. Values remain exact internally;
rounding only changes their display. Configure precision in
[Number formats](/production-modeler/settings/#number-formats).

Unconnected inputs need a supply. Select a diagnostic in **Messages** to reveal
the affected node, even inside another container.

## Clock and Somersloops

**Clock** scales recipe speed. `1` is rated speed; `2` doubles input and output
for the same machine count. Power follows the building's own rules.

**Somersloops** boost output without scaling material input in the same way.
Slot count, amplification, and power costs depend on the building.

Both controls respect the selected game's limits. Tune them on an expanded node
or in the Inspector. Multi-selection can apply one change to eligible machines
as a single undo step. The Summary includes supported shard and slot totals.

## What the solver does

- **None:** leave calculated values blank while arranging the graph.
- **Manual:** solve entered equalities.
- **Basic:** add limits and maximize flows.
- **Full:** also honor connection priority.

New models start in Full. Change modes in
[Settings](/production-modeler/settings/#calculation). Relevant edits schedule
a solve; **Calculate** starts one immediately. Long-running solves can be stopped
without deleting the model.

A **fixed rate** requires an exact flow. A **capacity ceiling** only caps it.
In Basic and Full, entering a fixed recipe count such as **2** plans its output
at the configured clock and sizes the Auto recipes downstream. Unfixed upstream
sources grow to supply it. If an upstream limit leaves a shortage, the downstream
plan stays visible and Messages reports the missing input. Connections show what
the upstream chain can supply; the fixed recipe's input shows what the plan needs.
The planned output requires that missing supply before it can run in the game.
Explicit port rates, downstream limits and recycling-loop balances still apply.
An unlimited alternate feed does not reset the downstream plan to one building:
automatic defaults remain large enough to carry your fixed production target.
Conflicting constraints, missing recipes, and unsupported behavior are reported
in Messages. Return flows in recycling loops are used before external supply.

App version, game-data version, and saved model revision are different values.
Include the details from **Help and about** when reporting unexpected results.

## Special buildings

Splitters and mergers route one part. Pipeline junctions route fluids or gases.
Outposts group a factory; blueprints scale repeated sections. Storage and buffers
represent throughput, not inventory filling over time.

Search the catalog for extractors, generators, assemblies, and mod-specific
buildings. Their controls depend on the selected pack. The
[special-buildings reference](/production-modeler/special-buildings/) covers
Modular Miners, Slug Hatcheries, Refined Power, FaxIT, and their limits.
