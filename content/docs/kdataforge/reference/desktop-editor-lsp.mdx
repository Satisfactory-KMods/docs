The standalone KDataForge Editor uses a Code-OSS workbench and a persistent language server. Open
a project containing your packs, then select the game-data archive for its game build and installed
mods. The editor and `kdf lint` use the same validation core.

## Import and bind game data

1. Start a Satisfactory world with KDataForge and the mods your pack targets. After the world
   begins play, run this in the **game console**:

   ```text
   KDF.DumpReflection --assets --functions --flattened
   ```

2. Find the ISO-named `.kdfdata` archive under `FactoryGame/KMods/ReflectionExport/`, or your
   chosen `--out` directory. See [Reflection Export](/kdataforge/reference/reflection-export)
   for chat defaults, options, and export validation.
3. Open **Datapacks**, choose **Import game data**, and select the archive. You can also drop
   one `.kdfdata` file into Datapacks. Import validates the archive and installs an immutable copy.
4. Review the imported data, then bind it to the active project. Importing an archive and
   selecting a project's binding are separate steps. Check the effective binding in project
   settings before relying on reflected completions or validation.

Use an export matching the game's build and mod set. Source archives may be up to 2 GiB;
import can losslessly compress stored text, but the installed archive must fit 512 MiB.

## Which reflection data is needed?

| Data | Enables |
| --- | --- |
| Classes, structs, enums, defaults, and native mappings | Reflected type/property lookup, value hints, and hover |
| `--flattened` / `classes.flat.ndjson` | The exported inherited-property view |
| `--functions` / class function records | Reflected template-function completion and signature checks |
| `--assets` / asset-by-class indexes | Object and asset lookup beyond texture records |
| `indexes/settings.json` | `session:`, `ags:`, and `option:` setting-id lookup |
| `catalog/cold_properties.json` and property `kdf` records | Reload classifications and cold-property explanations |
| Texture index and successful image records | Available texture previews |

The bare console export omits functions, non-texture asset indexes, and flattened classes.
The command above requests all three. Failed loads, stripped metadata, and unavailable pixels
still limit an otherwise usable archive; inspect its status and export diagnostics.

## Schema-only and limited data

Without usable game data, YAML editing and schema validation remain available. Newly created
projects start with an explicit schema-only binding until you choose an archive or Automatic
Vanilla in project settings. Projects without an explicit binding can use enabled bundled
Vanilla data when available. Disabling an explicitly bound datapack selects schema-only mode.

Schema-only mode cannot establish whether a reflected class, property, function, or asset exists.
Partial reflection is reported as limited data; missing records are not proof that game content
does not exist. Re-export with the needed options and matching mods, import, and review the
project binding when richer checks are needed.

## Diagnostics and server status

Review **Problems** and **KDF Validation** for diagnostic code, severity, message, and source
location. Check language-server status and error details when results stop updating. Check the
effective datapack and its completeness when reflected suggestions are missing. A connected
server in schema-only mode still provides useful YAML checks.

For enum-backed `Bitflags` properties, completion and Class Info omit named choices that available
reflection proves invalid. Missing `bitmaskMode`, exact option values, or property width limits those
checks; suggestions are not proof that every offered value is valid at runtime. Use one enum name
or numeric value, as described in
[Property Types](/kdataforge/features/property-types#enum-typed-enum-class-and-tenumasbyte).

Requests through the desktop language-server bridge time out after 15 seconds. If the same project,
connection, and server process are still active, the editor sends a best-effort `$/cancelRequest`
notification for the expired request. Cancellation delivery can fail; the request still reports its
original timeout error. Check server status before retrying.

For configuration-driven YAML, read [Pack Configuration](/kdataforge/features/pack-configuration),
[Templates & Typed References](/kdataforge/features/templates), and
[Configuration Expressions](/kdataforge/reference/config-expressions). Diagnostic coverage
depends on the available reflection data as well as the YAML itself.

## Other LSP clients

The `kdf-language-server` binary speaks LSP over stdio. A host can supply
`initializationOptions.kdf.datapackPath` with a `.kdfdata` path; an empty string explicitly
selects schema-only validation. The same setting is accepted through
`workspace/didChangeConfiguration`. Markdown, lazy completion documentation, snippets, and
signature label offsets follow the capabilities declared by the client.

For applying YAML permanently to Unreal asset packages, see
[UE Editor Integration](/kdataforge/reference/editor-integration).
