KDataForge exports every reflected type loaded by the running game. The export also includes
Blueprint-generated classes and the user-defined structs and enums found through the Asset
Registry. The exporter works on the game thread in bounded slices and writes JSON in the
background.

## Run

Wait until world begins play, then use console:

```text
KDF.DumpReflection
```

Or chat:

```text
/kdf-reflection
```

The two commands do **not** export the same amount:

| Start | Options it uses | Result |
| --- | --- | --- |
| Console `KDF.DumpReflection` (bare) | none | Classes, structs, enums, defaults, Blueprint mappings, textures, the settings index and the cold-property catalog in the final ZIP. **No** functions, **no** data-asset or curve indexes and **no** flattened classes. |
| Chat `/kdf-reflection` (bare) | `--assets --functions --flattened --pack --image-max-dimension=1024` | The full profile: everything above plus functions, asset indexes and flattened classes. |
| Launch argument `-KDFReflectionAutoExport=<dir>` | `--assets --functions --flattened` (and `--image-max-dimension` from `-KDFReflectionAutoImageMaxDimension=<n>` if given) | The same export, started automatically once a world has begun play. |

For the data KDataForge Tools needs (function completion in templates, asset-by-class indexes,
inherited properties) use the bare chat command, the auto export, or give the console command the
options yourself: `KDF.DumpReflection --assets --functions --flattened`. The chat defaults apply
only when you give **no** option at all; as soon as you pass one, exactly the options you passed
are used.

For KDataForgeJS projects, `kdf game-data` owns this lifecycle. It discovers a compatible Windows or Linux install,
loads the newest local save, launches with `-KDFReflectionAutoExport=<temporary-directory> -KDFReflectionAutoExit`, waits for atomic publication,
and imports the archive and generated declarations into the current project. `-KDFReflectionAutoExit` requests a clean
game exit after the automatic export finishes; it has no effect on manual exports.

The game emits `typescript/kdataforgejs/kdataforge.generated.d.ts` inside the temporary export. The CLI organizes that
file under `DataForge/typescript/kdataforgejs/`: `index.d.ts` references runtime declarations, globals, alphabetic
`satisfactory/` groups, and Unreal-path `paths/` groups. Pack authors use `index.d.ts` and do not edit generated files.

Clients do nothing unless `--force` is supplied. Server or host is normal export location. Default
directory is `FactoryGame/KMods/ReflectionExport/`.

| Option | Meaning |
| --- | --- |
| `--out <dir>` | Override output directory. |
| `--mounts /Game,/Plugin` | Restrict Blueprint discovery to comma-separated mount points. |
| `--assets` | Add asset-by-class indexes beyond textures; loading attempts still cover every selected registry asset. |
| `--asset-cap N` | Limit assets recorded per class. |
| `--functions` | Include reflected function signatures and flags (see [Functions](#functions)). |
| `--flattened` | Write inherited-property view to `classes.flat.ndjson`. |
| `--image-max-dimension N` | Largest exported texture side in pixels, `1` to `4096`; default `1024`. |
| `--used-textures[=true\|false]` | Select textures referenced by reflected non-widget class defaults; enabled by default. `false` selects all supported, portable texture candidates. |
| `--pack` | Compatibility no-op; final ZIP is always written. |
| `--skip-widgets` | Skip widget Blueprints; this is the default when omitted. |
| `--skip-widgets=true` | Skip widget Blueprints, same as `--skip-widgets`. |
| `--skip-widgets=false` | Include widget Blueprints, same as `--widgets`. |
| `--widgets` | Shortcut that includes widget Blueprints. |
| `--budget-ms N` | Game-thread budget per tick; default `8`. |
| `--batch-size N` | Blueprint load batch size; garbage collection runs between batches. |
| `--families name:path,...` | Extend linter catalog families. |
| `--force` | Allow local client export. |

Progress appears in chat and `LogKDFReflection`. Run `KDF.ValidateReflection [--out <dir>]` after
completion for runtime acceptance checks. Use the Python artifact validator for ZIP integrity,
file parity, images, and schema validation; see [Validation](#validation).

## Output

- `manifest.json`: runtime engine/build, platform, options, installed mods, counts, and failed loads.
- `classes.ndjson`, `structs.ndjson`, `enums.ndjson`: path-sorted records with inline property data.
- `classes.flat.ndjson`: optional inherited-property view.
- `indexes/subclasses.json`, `indexes/assets.json`: class and registry lookup indexes.
- `indexes/settings.json`: game settings that `session:`, `ags:` and `option:` references can read, see
  [Settings index](#settings-index).
- `catalog/cold_properties.json`: the cold-property catalog, see
  [Reload classification](#reload-classification-and-cold-property-catalog).
- `indexes/textures.json`: image path, format, dimensions, export method, or per-texture failure reason.
- `images/**`: selected texture images as PNG, proportionally limited to the configured
  `--image-max-dimension` cap (default `1024` pixels per side).
- `nativeMapping.json`: native-to-Blueprint and reverse mappings.
- `catalog/instanced_classes.json`: linter family catalog.
- `schema/reflection.schema.json`: draft 2020-12 schema.
- `<ISO-date>.kdfdata`: mandatory ZIP bundle containing every output file.

By default, texture selection recursively scans reflected non-widget class defaults. This retains descriptor, item,
recipe, and schematic icons while excluding material-only maps, widget-only decoration, unreferenced helper
textures, dynamic render/media textures, and transient runtime textures without a portable asset identity.
Selected textures remain uncapped and appear in `indexes/textures.json` with Asset Registry tags, source and
exported dimensions, resize state, image path, or explicit failure details. Every successful image is PNG.
Cooked BC/BC7 data is decoded before writing; GPU readback supplies pixels when cooked CPU data is unavailable.
Images exceeding the configured cap are proportionally downscaled or use a suitable cooked mip.
The cap does not upscale images. Missing or unreadable higher mips can produce smaller output even
when the source fits within the cap. Source/exported dimensions and `resized` record the result.
Cooked-decode and GPU-readback fallbacks warn when using a lower mip than requested; the raw
`platformMipPng` path does not. Unavailable textures remain indexed but produce no placeholder image.

Each encoded PNG is limited to 4 MiB (4,194,304 bytes). Larger previews are not written; their
texture metadata remains indexed with `status: error`, `errorCode: encodedImageTooLarge`, and an
increased image error count. Reduce `--image-max-dimension` and rerun the export to retry.

With `--used-textures=false`, selection expands to all supported, portable texture candidates,
including candidates not referenced by those defaults. The manifest's `options.usedTexturesOnly`
records that choice: `true` pairs with `options.textureSelection: reflectedNonWidgetClassDefaults`,
and `false` with `options.textureSelection: allPortableTextures`. `options.imageMaxDimension` records
the actual image cap; consumers should read it instead of assuming every export uses 1024.

Current exports containing `options.imageMaxDimension` must include both `options.usedTexturesOnly`
and `options.textureSelection` with the consistent pairing above. If either selection field is
present, its partner is required too. Legacy `schemaVersion: 1` exports may omit all three fields.

Exporter attempts to load every previously unloaded registry asset under configured mounts with
quiet/no-warn flags and bounded batches. Failed loads remain in manifest. Garbage collection runs through
engine safe points, never directly from ticker-time export code. `--assets` adds indexes for data assets,
curves, and other classes referenced by object properties; `--asset-cap` applies only to non-texture index
classes, not loading coverage.

Native constructors sometimes generate a fresh GUID, current timestamp, seed, transient object name,
or uninitialized byte sequence. Exporter detects volatile reflected types and values, emits reflected zero
value, and writes `defaultVolatile: true`. Result stays valid `ImportText` input and deterministic. Stable
constructor defaults remain unchanged. Blueprint-authored member names are emitted lowercase because Unreal's
case-preserving `FName` display casing depends on asset load order. Lookup remains case-insensitive.

To import, run **KDataForge: Switch datapack** in VS Code, select generated
`.kdfdata`, then bind the imported datapack to the project. KDataForge Tools validates manifest/schema, stores
immutable archive copy, and exposes contents as datapack `reflection` section to editor and language
server. See [VS Code Extension & LSP](/kdataforge/reference/vscode-extension-lsp) for project binding,
reflection requirements, and schema-only validation. Directory form is useful during
editor/language-server development.

Desktop import finds reflection data by `manifest.json` at the archive root, under `reflection/`,
or under `kdf/reflection/`. These prefixes are case-sensitive. Exactly one supported location may
contain a manifest, and `classes.ndjson` must be a file under that same prefix; class records at
another prefix cannot fill the gap. Multiple supported reflection manifests are rejected.

## Runtime export publication and recovery

The runtime exporter first writes loose files and the ZIP into a sibling directory named
`.<output-name>.kdf-export-<id>.stage`. Preparation failures leave existing output files unchanged.
Publication then replaces generated files individually, retiring obsolete generated files and
publishing the new `.kdfdata` archive last. Do not read, import, edit, or start another export into
that destination until completion. The whole directory is not replaced atomically.

Before publication, the exporter preserves affected existing files under
`.<output-name>.kdf-export-<id>.stage.backup/previous/`. Its `recovery.json` records the absolute
`destination`, new `archive` filename, `previousFiles`, `newFiles`, and `newDirectories`. Paths in
these three lists are relative to `destination`. A publication error attempts rollback and reports
whether it completed; the recovery directory remains available even after a completed rollback.

After every new file, including the archive, has been published, the exporter writes a sibling
`.<output-name>.kdf-export-<id>.stage.backup.committed` file containing the same journal. It removes
that marker only after removing the backup directory. A retained marker therefore records completed
publication, possibly with interrupted cleanup; it does not prove artifact validity or that every
backup file remains available. If writing the marker fails, publication can still succeed with a
warning and retained recovery directory. **An absent marker does not prove that publication failed.**

A process crash can interrupt publication or rollback. There is no automatic restart recovery.
If output is incomplete or its state is uncertain:

1. Stop the exporting game process and any other writer to that destination. Copy the destination,
   matching staging directory, recovery directory, and commit marker, if present, to a safe location.
   Keep these copies unchanged until recovery is verified.
2. Inspect the journal and logs to identify the transaction and its exact destination. Confirm that
   every listed relative path stays inside that destination and that no affected path traverses a
   symlink, junction, reparse point, or nested mount. Do not combine journals from different exports.
3. If a commit marker exists, validate the published output first (see [Validation](#validation)).
   A valid completed export needs cleanup only. Without a marker, also check logs and validate before
   deciding to roll back: the marker write itself may have failed after successful publication.
4. To restore the previous files, first check that **every** `previousFiles` entry exists under
   `backup/previous/`. If any is missing, stop; interrupted cleanup may have removed part of the
   backup. Recover from the safe copies or another known-good export instead of using a partial backup.
5. Remove only the destination files listed in `newFiles`, if present. Remove only empty directories
   listed in `newDirectories`, deepest first; preserve directories containing other files. Copy each
   `previousFiles` entry from `backup/previous/` back to the same relative destination path, creating
   parent directories as needed and overwriting the affected file. Restore any previous `.kdfdata`
   archive last. **Copy**, rather than move, so recovery sources stay intact.
6. Check restored files against the saved `previous/` bytes and verify that `newFiles` are absent.
   Validate a restored complete export with both validators below. If no previous complete export
   existed, verify the restored prior state and generate a fresh export into a new empty directory.
   Retain the journals, staging files, backup, marker, and safe copies until these checks succeed.

These names belong to **runtime export**. The metadata-merge commandlet uses separate
`.<output-name>.kdf-merge-<id>.stage` and `.backup` sibling directories and directory-move recovery,
explained under [Editor Metadata Supplement](#editor-metadata-supplement). Do not apply runtime
`recovery.json` steps to a metadata-merge backup.

## Functions

With `--functions` (included in the chat default and the auto export) each class record in
`classes.ndjson` gets a `functions` array. KDataForge Tools uses it to complete and check
[template function calls](/kdataforge/reference/reflection-export#functions).

| Field | Meaning |
| --- | --- |
| `name` | The function name, lowercased so exports of different runs compare equal |
| `authoredName` | The name with its authored letter case (`GetItemName`). Editors show this one. |
| `path` | `<ownerPath>:<name>` |
| `ownerPath` | The class that declares the function |
| `flags` | The function flags, for example native, `BlueprintPure`, `Const`, `Static`, net and event flags |
| `params` | Input parameters as property records, in declaration order |
| `return` | The return value as a property record; absent when the function returns nothing |

Property records use the same shape as class properties, including `authoredName`.

## Integer bitmask metadata

For integer properties with `Bitmask` and `BitmaskEnum` metadata, the exporter resolves only
already-loaded enums. A full enum path must identify a loaded enum; a short name must uniquely
match one. A resolved enum supplies its path, named `options`, and `bitflags` metadata. Plain
integer bitmask properties also advertise bitmask operations and the named `kdf.valueForm`. A
resolved enum with `Bitflags` metadata supplies
`bitmaskMode` on both integer-bitmask and enum-backed property records: `maskValues` when
`UseEnumValuesAsMaskValuesInEditor` metadata is present, and `bitIndices` otherwise. Consumers use
that mode and exact option values to derive declared bits. Enum-backed properties keep enum import
syntax; they do not get the pipe/sequence flag syntax or bitmask mutation operations used by plain
integer `BitmaskEnum` properties. Without `bitmaskMode`, enum-backed properties use exact enum
membership when complete option values are available. For plain integer bitmasks, an absent mode
limits editor checks; runtime still requires a valid enum result and a value that fits the property.
Missing metadata, an unloaded enum, or an ambiguous short name keeps the
numeric fallback. Export does not load an enum merely to resolve this metadata. Runtime support
requires `WITH_METADATA` and retained metadata; exported hints do not restore stripped runtime metadata.

These hints describe available editor choices. Runtime value conversion still follows
[Property Types](/kdataforge/features/property-types#bitmask-integer-properties-with-bitmaskenum-metadata),
including its mask-value, bit-index, and numeric forms.

## Settings index

`indexes/settings.json` lists the game settings that `session:`, `ags:` and `option:`
[references](/kdataforge/reference/reflection-export#settings-index) can read. It is written by every export.

| Field | Meaning |
| --- | --- |
| `schemaVersion`, `engineVersion` | Format and build |
| `counts` | Number of settings per provider: `session`, `ags`, `option`, `other` |
| `settings` | The records, sorted by provider, lowercase id and path |
| `unresolved` | Setting assets that could not be indexed, with a `reason` (for example an empty id) |

A record has:

| Field | Meaning |
| --- | --- |
| `id` | The setting id (`StrId`), exactly what follows the prefix in `ags:<id>` |
| `provider` | `session` (SML session setting), `ags` (advanced game settings), `option` (local game options) or `other` (not readable by a prefix) |
| `path`, `class`, `source` | The asset, its class, and which mod or the base game provides it |
| `displayName`, `tooltip` | The texts shown in game |
| `valueType` | `bool`, `int`, `float`, `string`, `color` or `other` |
| `default` | The default value when it can be read |
| `range`, `displayRange` | Slider or selection bounds; `displayRange` only when it differs |
| `options` | `{value, label}` choices of an integer selector |
| `placements` | Options-menu locations. Each entry contains category, optional subcategory and row priority; categories include class, display name and menu priority. |
| `sessionWide`, `dedicatedServerRelevant` | Whether the setting is stored per session and whether a dedicated server uses it |
| `managerClass`, `mapWhitelist` | The manager that owns the setting and, for session settings, the maps it is limited to |

Active runtime-generated KDataForge sound sliders are included as `option` records with stable virtual
paths and their **Options → Audio** placement. Dedicated servers do not create local Audio settings,
so their exports omit these runtime-only records.

The editor completes setting ids from this file and reports an unknown id as `setting.unknown-id`
when the file exists.

## Reload classification and cold-property catalog

Every property declared directly by a class carries two extra fields under its `kdf` object:

| Field | Meaning |
| --- | --- |
| `kdf.reload` | `hot`, `cold` or `newActors` |
| `kdf.reloadReason` | One sentence that says why, present when the classification comes from the catalog |

- `hot`: a write applies live (an explicit allow-list entry).
- `cold`: the game reads the property once or only when an object is created, so a live write does
  not change existing state.
- `newActors`: the class default belongs to an actor or component, so only newly spawned actors see
  a write (the patch can set `applyToSpawnedActors: true` to include existing actors).

Struct members, function parameters and container elements inherit the classification of the
class property that contains them. The editor shows the classification next to `path:`
completions and reports operations on cold or `newActors` properties as `property.cold`, see
[Reload classification](/kdataforge/reference/reflection-export#reload-classification-and-cold-property-catalog).

`catalog/cold_properties.json` is the catalog behind it: `version`, a `description`, and
`entries` of `{class, property, reload, reason, verified}`. A class entry includes its subclasses
and the property name is case-insensitive. `verified: false` marks an entry that is a reasonable
assumption not yet checked in game.

## Editor metadata supplement

Packaged game may have `WITH_METADATA` disabled. Runtime records then contain
`metadataAvailable: false`; export still succeeds. Generate metadata in modding editor:

```powershell
UnrealEditor-Cmd.exe FactoryGame.uproject -run=KDFReflectionMetaExport -out=C:\Temp\KDFMeta
```

Merge supplement into separate copy with same native commandlet:

```powershell
UnrealEditor-Cmd.exe FactoryGame.uproject -run=KDFReflectionMetaExport `
  -runtime=C:\Path\ReflectionExport `
  -supplement=C:\Temp\KDFMeta\metadata.supplement.json `
  -out=C:\Path\ReflectionMerged
```

Merge records editor and game build per field and rebuilds mandatory ISO-named `.kdfdata` ZIP. The
`-runtime` and `-out` directories must not overlap: they cannot be equal, and neither may contain the
other. The `-supplement` file must be outside the `-out` directory, especially when using `-force`,
which replaces an existing merge output directory. These path checks also apply without `-force`.

On Windows and Linux, checks compare normalized paths and resolved physical paths, so symlink or
junction aliases cannot bypass either restriction. Subsequent merge reads and writes use those
resolved paths. The runtime directory and supplement file must exist. A new output path may have
missing parent directories: the commandlet resolves its nearest existing directory ancestor and
appends the missing components. Empty, inaccessible, dangling, or otherwise unresolvable paths
are rejected before an existing output is replaced. Unsupported platforms reject the merge.

The commandlet prepares a complete merged export and `.kdfdata` archive in a uniquely named
sibling directory before replacing `-out`. Copy, metadata parsing, manifest, or archive errors
during preparation leave an existing output untouched. The runtime manifest's `generatedAt`
must be nonempty and contain no path separators because it supplies the archive filename.
Keep the input and output directories unchanged until the commandlet finishes; do not run
concurrent merges into the same output.

With `-force`, the previous output moves to a uniquely named sibling backup before the prepared
export moves into place. If publication fails, the commandlet tries to restore the backup. If
restoration also fails, the error reports the backup path containing the previous output. Resolve
any conflicting entry at `-out`, then move that backup directory back to `-out`. A successful merge
removes its backup; a cleanup warning reports any backup retained for manual removal. Preparation
failures also attempt to remove their staging directory and report its path if cleanup fails.

These directory moves require same-filesystem rename support without replacing an existing
entry. Linux requires `renameat2` with `RENAME_NOREPLACE`; unsupported kernels or filesystems
reject publication. Replacement uses two directory moves, so an interrupted process can leave
`-out` absent with the previous export in a sibling `.<output-name>.kdf-merge-<id>.backup`
directory. Inspect any matching `.stage` and `.backup` directories before recovering or deleting
them; staging directories may contain incomplete exports.

Before `-force` replaces an existing output directory, the commandlet inspects its contents
without following link targets. Any nested symlink or Windows reparse point blocks replacement,
even if its target is unrelated to the inputs. On Linux, mount points also block replacement,
including bind mounts on the same filesystem and an output directory that is itself a mount point.
The resolved output target must share its parent's mount ID, and every nested entry must share
that same mount ID. Mount IDs must be readable through `/proc/self/fdinfo`; if they cannot be
verified, replacement is rejected. Unreadable entries, failed directory enumeration, or more than
1,000,000 entries also block replacement. Unmount mounted entries, remove other
blocked entries, or choose a new output directory, then retry.

No Python merge script is packaged into mod or archive.

## Validation

Run both validators after export completes:

| Validator | Checks |
| --- | --- |
| In-game `KDF.ValidateReflection [--out <dir>]` | Required live FactoryGame reflection shapes, authored user-struct member names, and sampled default `ExportText`/`ImportText` round trips (up to three per property kind). Checks required file presence, exactly one `.kdfdata` file, the `FGUnlockRecipe` Blueprint mapping, and basic settings, icon, and cold-property index structure when present. |
| Python `validate_reflection_export.py <directory>` | Exported reflection contracts and records against the emitted draft 2020-12 schema; texture PNG integrity, dimensions, selection options, image/index consistency, and supported optional index/catalog checks. Requires exactly one ISO-named `.kdfdata` ZIP, sorted entries, valid ZIP CRCs, every generated file in the ZIP, and byte-for-byte agreement between each packed entry and its loose file. Unrelated regular custom files outside `images/` may remain outside the archive. Also checks numeric integer `schemaVersion: 1` and mirrors the editor's archive inspection gates: source archive at most 2 GiB, at most 20,000 entries, at most 4 GiB expanded, `manifest.json` at most 1 MiB, and each PNG within the 4 MiB preview limit. |

ZIP entries and indexed image paths must use safe relative paths contained within the export
directory; traversal paths are rejected. The Python validator rejects symlinks and Windows reparse
points anywhere in the loose export tree, including unrelated custom entries. Regular custom files
outside `images/` remain permitted outside the generated archive.

The Python validator checks PNG signatures, chunk boundaries and CRCs, and supported non-interlaced
pixel layouts with valid bit-depth and color-type combinations. It requires a single first `IHDR`,
valid `PLTE` placement and size when present, a palette before indexed image data, contiguous `IDAT`
chunks, and an empty final `IEND` with no trailing bytes. It also checks the decoded byte count,
complete compressed stream, and row filter values. Chunk types must contain four ASCII letters
with an uppercase third letter. Unsupported critical chunks are rejected; unknown ancillary chunks
remain permitted. Invalid structure is rejected even when CRCs and dimensions match.

Native acceptance PASS does not verify ZIP contents, loose/packed parity, image integrity, or
schema conformance. Use the Python artifact/package validator before distributing or importing an
artifact. The editor can compact source archives larger than 512 MiB and rejects installed output
that still exceeds its 512 MiB cache cap. Python PASS does not predict compacted-cache success or
prove every extension import gate. Confirm acceptance through **KDataForge: Switch datapack** in VS Code.
The Python validator reads an export directory containing loose files and its
`.kdfdata` archive; a standalone archive must first be extracted into a directory alongside that archive.

Install Python dependency and validate one export from the modding workspace:

```powershell
python -m pip install jsonschema
python Mods/GameFeatures/KDataForge/Tools/validate_reflection_export.py `
  C:\Path\ReflectionExport
```

For deterministic comparison, validate both exports with `--compare`:

```powershell
python Mods/GameFeatures/KDataForge/Tools/validate_reflection_export.py `
  C:\Path\ReflectionExport --compare C:\Path\SecondReflectionExport
```

Comparison hashes loose file paths and contents with SHA-256, excluding `.kdfdata` archives.
It canonicalizes `manifest.json` and omits only its `generatedAt` field; other loose files are
hashed as bytes. Each export must pass artifact validation before hashes are compared.

## Limits

- Blueprint load failures remain in `manifest.json.failedLoads` with reason.
- Dedicated-server cooks or unsupported GPU formats may expose no readable pixels. Such records contain
  failure details instead of image bytes.
- Per-class cap applies to non-texture classes.
- All-mount exports can be large, especially with functions, flattened records, assets, or widgets.
- Tick budget is checked between reflected records and Blueprint loads. One synchronous Asset
  Registry query, Blueprint load, garbage collection, or unusually large type can exceed budget by
  its own execution time because Unreal does not expose resumable versions of those operations.
- Output determinism assumes identical game build, mod set, options, and registered content.
