KDataForge uses mod unlocks in schematic and delivery-task `unlocks:` lists exactly like base-game
classes. The mechanism is fully generic (resolve `class:`, `NewObject` it onto the schematic's CDO,
apply `properties:`, append to `mUnlocks`), so mod-provided classes need no special handling. Known
native paths with Blueprint variants automatically remap; exact Blueprint paths also work. Catalog
reflects mods loaded during Unreal scan.

Use these in a schematic's
[instanced unlocks list](/kdataforge/features/schematics#instanced-unlocks-the-normal-way-to-wire-up-a-recipe)
or in a standalone [type: unlock](/kdataforge/features/unlocks) document. For base-game classes see
[Base-Game Unlock Classes](/kdataforge/reference/base-game-unlock-classes).

:::caution
These classes exist only when provider mod is installed. Gate optional integrations with a
[`hasMod` condition](/kdataforge/features/conditions-and-packs); otherwise unresolved class is
reported by `/kdf report` and skipped.
:::

Use Blueprint generated-class path where listed because it carries mod-configured defaults.
Concrete classes without Blueprint use native `/Script/<Module>.<Class>` path.

YAML encoding follows [base-game types](/kdataforge/reference/base-game-unlock-classes): `bool`,
`int32`, and enum values are scalars; `TSubclassOf<T>` and `TObjectPtr<T>` use Unreal paths;
`TArray<T>` uses a sequence; reflected structs use mappings. Inherited fields keep the same type.

## KLib fields

```yaml
unlocks:
  - class: /KLib/Unlocks/BP_GiveToPlayersUnlock.BP_GiveToPlayersUnlock_C
    properties:
      - path: mAmounts
        value:
          - ItemClass: /KDataForge/Gen/MyPack.Gen_MyPack_MySuperIngot_C
            Amount: 10
```

| Class                         | Fields and accepted types                                                                                                                                                                                                                                     | Purpose                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `KLGiveItemToAllPlayerUnlock` | `mAmounts: TArray<FItemAmount>`, `bCanRepeat: bool`                                                                                                                                                                                                           | Gives listed items to every player                                                                                            |
| `KLUnlockMaxRepeatPurchases`  | `mMaxPurchaseCount: int32`, `mCostMultiplierCurve: TObjectPtr<UCurveFloat>`, `mRewardMultiplierCurve: TObjectPtr<UCurveFloat>`, `mRewardItemsByLevel: TArray<FKLRepeatPurchaseRewardLevel>`, inherited `mAmounts: TArray<FItemAmount>` and `bCanRepeat: bool` | Level-dependent repeat purchases and rewards, deposited once into Trading Post storage (overflow spawns in a crate beside it) |
| `UKLUnlockCleanerItem`        | `mItemDescriptor: TSubclassOf<UFGItemDescriptor>`                                                                                                                                                                                                             | Info-only cleaner item entry; extends `FGUnlockInfoOnly`, so it grants nothing by itself                                      |
| `KLNetworkLevelUnlock`        | —                                                                                                                                                                                                                                                             | Deprecated Faxit tier recompute hook                                                                                          |
| `KLUnlockExtractorScanner`    | inherited `mResourcesToAddToScanner: TArray<TSubclassOf<UFGResourceDescriptor>>` (legacy), `mResourcePairsToAddToScanner: TArray<FScannableResourcePair>`                                                                                                     | Deprecated; use `FGUnlockScannableResource`                                                                                   |

`KLUnlockMaxRepeatPurchases.mMaxPurchaseCount <= 0` means unlimited. Cost/reward curve X is number
of completed purchases, so X=0 controls first purchase and X=1 the second. A null curve property
uses multiplier 1, leaving the configured value unchanged. Full worked pack:
[Repeat-Purchase Schematic (KLIB)](/kdataforge/examples/repeat-purchase-schematic).

### Mod struct value shapes

| Struct field                                    | Accepted type         | Constraint / meaning                                                                                                       |
| ----------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `FKLRepeatPurchaseRewardLevel.mPurchaseLevel`   | `int32`               | Minimum 1. First purchase is level 1; highest configured level not above current purchase wins.                            |
| `FKLRepeatPurchaseRewardLevel.mItemsToGive`     | `TArray<FItemAmount>` | Reward items for this level. See [base struct shapes](/kdataforge/reference/base-game-unlock-classes#struct-value-shapes). |
| `FKLRepeatPurchaseRewardLevel.bOverrideCosts`   | `bool`                | When true, replaces normal costs with `mCosts`.                                                                            |
| `FKLRepeatPurchaseRewardLevel.mCosts`           | `TArray<FItemAmount>` | Replacement costs when `bOverrideCosts` is true.                                                                           |
| `FKLRepeatPurchaseRewardLevel.mAdditionalCosts` | `TArray<FItemAmount>` | Costs added only at this exact level.                                                                                      |

`mItemsToGive` replaces the complete reward list from its level onward. `bOverrideCosts: true`
replaces the complete raw cost list from that level onward; `mAdditionalCosts` applies only when
`mPurchaseLevel` matches the current purchase exactly and does not carry forward. Both cost lists
are raw values, combined before `mCostMultiplierCurve` is applied.

Runtime-only `mCached*` and `bHasCached*` members are transient caches, not KDataForge configuration
fields, so they are intentionally excluded.

### Deprecated KLib unlocks

`KLNetworkLevelUnlock` carries no data of its own and only forces a Faxit tier recompute; use the
`KPCLFaxit*Unlock` classes below instead. `KLUnlockExtractorScanner` is superseded by the base-game
`FGUnlockScannableResource`. Both still exist because shipped schematic assets instance them, so do
not use either in a new pack.

## KPrivateCodeLib fields

```yaml
unlocks:
  - class: /KPrivateCodeLib/Unlocks/BP_FaxitCapaUnlock.BP_FaxitCapaUnlock_C
    properties:
      - path: mCapacityType
        value: Drive
      - path: mAmount
        value: 1
  - class: /KPrivateCodeLib/Unlocks/BP_FaxitSpeedUnlock.BP_FaxitSpeedUnlock_C
    properties:
      - path: mAmount
        value: 15000 # fluid units per minute, 1000 units = 1 m³
      - path: bIsFluid
        value: true
```

| Class                                 | Fields and accepted types                                         | Purpose                                                            |
| ------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| `KPCLDeliveryTaskUnlock`              | —                                                                 | Enables delivery tasks, the research queue, and manual delivery    |
| `KPCLDeliveryTaskInventorySlotUnlock` | `mNumInventorySlotsToUnlock: int32` (min 1)                       | Adds slots to the shared delivery-task manual-input inventory      |
| `KPCLDeliveryTaskQueueSlotUnlock`     | `mAmount: int32` (min 1)                                          | Raises how many delivery tasks queue at once (limit starts at one) |
| `KPCLFaxitCapacityUnlock`             | `mCapacityType: EKPCLFaxitCapacityType`, `mAmount: int32` (min 1) | Raises machine-network, network, or drive capacity                 |
| `KPCLFaxitFeatureUnlock`              | `mFeature: EKPCLFaxitFeature`                                     | Enables RemoteAccess, Sink, or Depot                               |
| `KPCLFaxitSpeedUnlock`                | `mAmount: int32` (min 1, default 15), `bIsFluid: bool`            | Raises solid/fluid transfer rate                                   |
| `KPCLDeliveryTaskSlotUnlockBase`      | —                                                                 | Abstract delivery-slot base; never instance directly               |
| `KPCLFaxitUnlockBase`                 | —                                                                 | Abstract Faxit base; never instance directly                       |

Slot/capacity amounts clamp to minimum 1. Faxit speed uses items/min for solids (`mAmount: 15` adds
15 items/min) and fluid units/min for fluids (1000 units = 1 m³, so `mAmount: 15000` adds 15 m³/min).
Faxit unlock values accumulate: every purchase recomputes from base values and reapplies each
purchased unlock, so there are no tiers and no curves — two capacity unlocks of 1 give the same
result as one unlock of 2.

| Enum type                | Accepted YAML values                 | Meaning                                                    |
| ------------------------ | ------------------------------------ | ---------------------------------------------------------- |
| `EKPCLFaxitCapacityType` | `MachineNetwork`, `Network`, `Drive` | Machine-network limit, network building limit, drive slots |
| `EKPCLFaxitFeature`      | `RemoteAccess`, `Sink`, `Depot`      | Faxit feature gate enabled by the unlock                   |

See [Base-Game Unlock Classes](/kdataforge/reference/base-game-unlock-classes) for FactoryGame
classes and [Availability Dependency Classes](/kdataforge/reference/availability-dependency-classes)
for gating classes.
