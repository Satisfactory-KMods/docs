Availability dependencies gate content without granting rewards. KDataForge instances them in four
explicit lists:

- schematic `dependencies:` → `UFGSchematic::mSchematicDependencies`;
- research `unlockDependencies:` → `UFGResearchTree::mUnlockDependencies`;
- research `visibilityDependencies:` → `UFGResearchTree::mVisibilityDependencies`;
- KAPI delivery-task `dependencies:` → `UKAPIDeliveryTask::mTaskDependencies`.

Each entry uses a block map containing `class:` and `properties:`. Known native paths with Blueprint children automatically
remap to concrete generated classes; exact Blueprint paths remain valid. Linter emits warning
`class.native-remapped` for mapped native form. Abstract classes without Blueprint variants cannot
be instanced.

```yaml
dependencies:
  - class: /Script/FactoryGame.FGSchematicPurchasedDependency
    properties:
      - path: mSchematics
        value:
          - /Game/FactoryGame/Schematics/Progression/Schematic_1-1.Schematic_1-1_C
      - path: mRequireAllSchematicsToBePurchased
        value: true
```

Each `properties` entry's `path` uses exact reflected member name. `TSubclassOf<T>` accepts Unreal class path;
`TObjectPtr<T>` accepts object asset path or `null`; `TArray<T>` accepts YAML sequence;
`TMap<TKey, TValue>` accepts YAML mapping with keys and values matching declared generic types.
`TEnumAsByte<E>` accepts same enum token as `E`. C++ access (`protected`/`private`) does not change
property path because KDataForge writes through Unreal reflection.

## Regenerate inventory

Run `Mods/GameFeatures/KDataForge/Tools/scan_instanced_class_catalog.py` inside Unreal Python. It
combines Asset Registry's transitive derived-class set and Blueprint `ParentClass` tags with native
header metadata, then writes `Saved/KDataForge/instanced-class-catalog.json` by default. Set
`KDF_CLASS_CATALOG_OUTPUT` to write a temp comparison file instead. The bundled
`KDataForge-Linter/src/kdataforge_linter/catalogs/instanced_classes.json` snapshot already matches
the current Unreal scan, so it does not need regeneration unless classes or Blueprint variants
change.

```yaml
type: research
research:
  - id: MyTree
    unlockDependencies:
      - class: /Script/FactoryGame.FGItemPickedUpDependency
        properties:
          - path: mItems
            value:
              /Game/FactoryGame/Resource/RawResources/SAM/Desc_SAM.Desc_SAM_C: 1
    visibilityDependencies:
      - class: /Script/FactoryGame.FGGamePhaseReachedDependency
        properties:
          - path: mGamePhase
            value: EGP_EarlyGame

conditions:
  hasMod: KAPI

  - id: MyDeliveryTask
    class: /Script/KAPI.KAPIDeliveryTask
    dependencies:
      - class: /Script/FactoryGame.FGSchematicPurchasedDependency

          - path: mSchematics
```
