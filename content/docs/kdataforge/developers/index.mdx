Use this section when your mod needs to depend on KDataForge from C++. Pack authors who only write
YAML can start with [Getting started](/kdataforge/getting-started).

## Choose the smallest integration

| Your goal | Integration |
| --- | --- |
| Let packs edit your classes or assets | Expose reflected properties. Built-in `cdo` targeting already handles them. |
| Ship YAML with your mod | Add KDataForge as a plugin dependency and place the files under your mod's `DataForge/` directory. |
| Add another YAML `type:` | Link `KDataForgeApi` and `KDataForge`, implement a native handler, then register it during the SML game-instance `CONSTRUCTION` phase. |
| Generate or inspect game-data metadata | Use the [reflection export](/kdataforge/reference/reflection-export) and bind its `.kdfdata` archive in the [desktop editor](/kdataforge/reference/desktop-editor-lsp). |
| Bake supported `cdo` changes into editor assets | Use [`KDF.ApplyToAssets`](/kdataforge/reference/editor-integration) in an Unreal Editor build. |

Most mods need only reflected properties and a YAML pack. A custom handler is useful when a new
document needs its own validation, load stage, generated objects, or runtime side effects.

## Public contracts

`KDataForgeApi` contains the handler contract: `IKDFDataEditorHandler`, `UKDFHandlerBase`,
`FKDFNode`, `EKDFStage`, operation enums, diagnostics, and apply/export contexts. Registering a
handler uses `UKDFSubsystem`, which lives in the main `KDataForge` module. Link both modules for a
native handler.

The main module also exposes selected integration services for generated content, queued content
registration, actor patches, resource-node rules, content removal, pack configuration, reload
events, and editor export. Their contracts and timing limits are listed in
[API design](/kdataforge/reference/api-design).

Use the [Template provider API](/kdataforge/reference/template-provider-api) to add custom
`{prefix:body}` values. Use the
[Blueprint configuration API](/kdataforge/reference/blueprint-config-api) when a mod menu needs to
read or change generated pack settings.

Do not link `KDataForgeYaml` to receive documents. KDataForge parses YAML before dispatch and gives
handlers an `FKDFNode` tree. `KDataForgeEditorUI` is the in-game editor, while
`KDataForgeLocalization` is an Unreal Editor module. Neither belongs in a normal handler
dependency list.

## Start a native integration

[Integrate KDataForge](/kdataforge/developers/integrate-kdataforge) covers the plugin dependency,
module dependencies, lifecycle registration, handler contracts, server builds, and verification.
The [handler template](/kdataforge/reference/handler-template) provides the complete C++ skeleton.
