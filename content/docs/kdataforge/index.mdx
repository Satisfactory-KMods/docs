KDataForge loads YAML packs that change or add Satisfactory content at runtime. Choose the path
that matches what you need to do.

## I use packs

Start with the [Player guide](/kdataforge/players). It explains how to install, update, remove, and
troubleshoot a pack without requiring YAML or Unreal Engine knowledge.

For multiplayer, install the same pack versions on the host or dedicated server and every client.
Each game process loads its own files. KDataForge does not transfer packs, compare checksums, or
reject mismatched pack sets during connection.

## I create YAML packs

Follow [Create your first pack](/kdataforge/getting-started) to make one visible recipe change and
verify it in game. Continue with the [How-to guides](/kdataforge/tutorials) when you have a specific
goal, such as adding an item and recipe, localizing a pack, or integrating another mod.

Open [Authoring concepts](/kdataforge/concepts) for the pack, document, target, operation,
identity, reload, multiplayer, and tool-choice model. Then use
[Document types and authoring features](/kdataforge/features) for the capability you need.
The [Examples](/kdataforge/examples) provide complete packs, while the
[Reference](/kdataforge/reference) holds exact fields, defaults, constraints, and API contracts.

Before distributing a pack, run [Lint your pack](/kdataforge/lint-your-pack).

When YAML is not enough, the KDataForgeJS dev build lets a pack carry typed TypeScript scripts: hooks on
Blueprint events, delegate bindings, and items or recipes with class-specific properties. Start with
[TypeScript scripting with KDataForgeJS](/kdataforge/features/typescript-scripting) for the project layout,
generated types, runtime APIs, and current security boundaries.

## I develop native mods or KDataForge

Start with the [Native developer guide](/kdataforge/developers) for module dependencies,
registration timing, and a minimal handler. Use [Contributor internals](/kdataforge/background)
for the runtime pipeline, persistence model, multiplayer boundaries, and module layout. Native extension points live in
[API design](/kdataforge/reference/api-design) and the
[handler template](/kdataforge/reference/handler-template). The
[UE editor integration](/kdataforge/reference/editor-integration) documents `KDF.ApplyToAssets`.

## Runtime tools

| Command | Where | What it does |
| --- | --- | --- |
| `/kdf report` | Chat | Shows detected packs, applied documents and operations, warnings, and errors. |
| `/kdf reload` | Host or dedicated-server administrator chat | Rescans and reapplies packs in that game process after initial loading. Run `/kdf report` afterward. |
| `KDF.Reload` | Host or server console | Runs the same reload and writes its summary to the log. |
| `/kdf config dump\|set\|apply` | Chat; writes require host or dedicated-server administrator | Inspects, stages, and applies pack settings. |
| `/kdf editor` | Chat; opens a host-local UI | Requests the in-game editor for live property edits, pack authoring, undo and redo, and YAML export. This branch has no host/admin permission check. |
| `/kdf sound <PackRef> <Id>` | Local player controller | Previews a generated sound on that machine. |
| `KDF.Editor` | Console | Runs the same editor toggle. |
| `/kdf debug on\|off` | Chat | Enables or disables global debug logging. With no argument, it toggles the current state. |
| `KDF.Debug 1` | Console or `-KDFDebug` launch argument | Logs one `[KDF DEBUG]` line for each applied operation, including editor edits. |
| `KDF.ApplyToAssets [PathFilter]` | Unreal Editor console only | Applies supported YAML patches to editor assets and marks their packages dirty. |

See [Commands and console variables](/kdataforge/reference/commands) for every chat, runtime
console, reflection, and Unreal Editor command, including permissions and process boundaries.

Reload is process-local. Frozen registrations, irreversible world changes, properties classified as
cold, and packs that generate native CDO helper assets still require a restart. While native helper
assets are active, KDataForge refuses manual and automatic reload before restoring properties.
