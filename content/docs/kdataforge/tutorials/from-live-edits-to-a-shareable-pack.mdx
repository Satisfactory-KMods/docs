`/kdf editor` has two workspaces. **Runtime** inspects loaded objects and applies property edits to
the current process. **Packs** creates and edits YAML files on disk. A live edit lasts only for the
current session, while a saved pack can be reloaded, restarted, versioned, and distributed.

This guide retunes a recipe in Runtime, exports the change, and places it in a pack created through
the Packs workspace.

## Before you start

You need a running game with KDataForge and a recipe you can test. In multiplayer, use the same pack
files on the host or dedicated server and every client. KDataForge does not transfer files or live
editor operations between processes.

Open the editor with `/kdf editor`. The top toolbar switches between **Runtime** and **Packs**.

## Test the change in Runtime

1. Select **Runtime**.
2. Choose **Recipes**, then search for the recipe you want to change.
3. Select the recipe and find `mManufactoringDuration` in the inspector.
4. Commit a new value. The editor applies the change through the same operation pipeline used by
   YAML patches.
5. Craft the recipe and check its duration.

Runtime keeps an undo and redo history for the current session. The side panel also shows YAML,
the recorded diff, references, and applied operations for the selected object.

## Export the tested change

Use **Export Diff** for a focused patch. When the selected object has active live-editor operations,
the export writes those operations with their arguments. If it has none, the handler falls back to
the top-level properties that received a first-write snapshot in the current session. An earlier
YAML operation can create such a snapshot. Opening a property without writing it does not.

**Export Full** writes every reflected property that is not deprecated, transient, or editor-only.
This can freeze unrelated defaults at their current values, so use it only when you intend to own
the full reflected state.

1. Keep the edited recipe selected.
2. Select **Export Diff**.
3. Read the status line for the written path.

The editor creates the destination directory when needed and writes:

```text
<ProjectDir>/DataForge/exported/<ObjectName>.cdo.yml
```

For a class default object, `<ObjectName>` is usually an Unreal name such as
`Default__Recipe_IngotIron_C`. The filename does not determine the target. The YAML inside the file
contains the target path.

A one-property export looks like this:

```yaml
type: cdo
patches:
  - target: /KDataForge/Gen/KDFSample.Gen_KDFSample_Recipe_SuperIngot
    properties:
      - path: mManufactoringDuration
        op: set
        value: 2.0
```

## Create the destination pack

1. Switch to **Packs**.
2. Under **New Pack**, enter a name containing letters, numbers, `_`, or `-`.
3. Select **Create**.

The editor creates this folder and manifest:

```text
<ProjectDir>/Mods/DataForge/<pack-name>/
  pack.yml
```

The manifest starts with a stable `ref`, the same display name, version `1.0.0`, a placeholder
description, priority `100`, `enabled: true`, and `debug: false`. Edit the description and version
before distribution. Treat `ref` as permanent after players have used generated content from the
pack.

If you already have a pack, select it in **Pack Browser** instead of creating another one.

## Put the export in the pack

You can move the exported `.cdo.yml` file into the new pack directory with a file manager. Select
**Refresh** in Pack Browser after moving it.

You can also create the destination file in the editor:

1. Select the pack in **Pack Browser**.
2. Under **New Document**, choose `cdo`.
3. Enter a filename without an extension and select **Create document**. The editor adds
   `.cdo.yml` automatically.
4. Open the exported file in a text editor and copy its YAML.
5. In KDataForge, select **Raw YAML** and replace the generated skeleton with the exported YAML.
6. Switch to **Form**. The editor parses the raw text before opening the form. Invalid YAML keeps
   you in Raw YAML and reports the parse error.
7. Select **Save**.

Save validates the YAML and replaces the file on disk. If the replacement fails, the original file
is preserved. The status line gives the exact path and reminds you to run `/kdf reload`.

## Edit pack files in Form or Raw YAML

The **Form** view exposes the parsed YAML tree. Select a node to replace it, add a child, remove it,
or use contextual suggestions for fields, classes, properties, and known values. The form preserves
handler-supported values that do not have a specialized control as raw YAML nodes.

Use **Raw YAML** for multi-document files, larger edits, or direct pasting. Switching back to Form
parses the current text and synchronizes the tree. Save always parses again before writing.

The editor tracks unsaved changes to the open file:

- **Save** writes them to disk.
- **Revert** reloads the selected file and discards the unsaved version.
- Switching to another pack or file is blocked until you save or revert.
- Creating another pack or document is also blocked while the current file is dirty.
- Closing the editor from the Packs workspace shows a warning with **Cancel** and
  **Discard and close**.

**Refresh** updates Pack Browser after files were added or moved outside the editor. It is not a
replacement for Save or Revert.

## Apply and verify the saved pack

1. Run `/kdf reload` as the host or a dedicated-server administrator.
2. Run `/kdf report` and confirm that the pack and document loaded without an Error.
3. Test the recipe again.
4. Restart the session if the report or feature page marks the change as cold, frozen, or
   restart-bound.

Reload restores captured property baselines, rescans the files, and reapplies the current pack set
in that process. Frozen content registrations, irreversible world changes, and packs using native
CDO helpers still require a restart.

## Create new documents directly in Packs

The Packs workspace can create typed documents for CDO patches, gameplay tags, assets,
localization, generated classes and content, data assets, curves, sink points, resource nodes,
sublevels, sounds, and pack configuration. Each new file gets the correct
`<name>.<type>.yml` suffix and a valid starting shape for that type.

This is the preferred editor workflow for new pack files. Follow the relevant feature page to fill
the generated document because a valid skeleton does not contain the gameplay data for a finished
item, recipe, schematic, or world rule.

## Runtime Create drafts

Runtime also retains a **Create** panel for drafting an item, resource, building, recipe, schematic,
research tree, unlock, data asset, or generic class from a loaded parent. It writes the selected
parent's current reflected values to:

```text
<ProjectDir>/DataForge/created/<Id>.<Kind>.yml
```

The editor creates the `created` directory when needed. This action writes a draft and does not
apply the new content to the running session. Move the reviewed draft into a named pack and restart
when its content registration requires it. For new work, the Packs workspace usually avoids this
extra staging step.

## Troubleshooting

### Export Diff contains little or nothing

Diff includes properties written on the selected object during the current session. Confirm that
you committed the value and still have the same object selected. Browsing a row does not record a
snapshot.

### An undone property still appears in Export Diff

Undo removes its live operation. The first-write snapshot remains, so after you undo every active
operation the fallback export can still include the current top-level property value. Review the
YAML and remove a no-op property before publishing if you do not want the pack to own it.

### Export Full contains internal-looking fields

Full export includes reflected fields even when Unreal does not mark them as normally editable. It
excludes deprecated, transient, and editor-only fields. Review the output and prefer Diff for a
small balance patch.

### Form will not open

Raw YAML contains a parse error or a document root that is not a map. Read the status line, correct
the raw text, then switch to Form again. You can use the [linter](/kdataforge/lint-your-pack) for
schema checks beyond parsing.

### A saved change has no effect

Save writes the file but does not apply it. Run `/kdf reload`, inspect `/kdf report`, and follow any
restart rule for the affected document or property. A generated content draft may require a
restart because the game registry has already frozen its session state.

### Another player does not see the change

Live edits and reloads are process-local. Copy the saved pack to every multiplayer process and use
the same version on the server, host, and clients.

[Getting started](/kdataforge/getting-started) covers pack discovery and reporting.
[Targeting](/kdataforge/features/targeting) explains selectors and spawned-actor patches. The
separate [UE Editor integration](/kdataforge/reference/editor-integration) applies YAML to Unreal
Editor assets with `KDF.ApplyToAssets`; it is not the in-game `/kdf editor` workflow.
