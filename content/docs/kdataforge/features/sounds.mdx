`type: sound` imports WAV or FLAC files from your pack as generated `UAkAudioEvent` assets.
Use it when an existing game or mod feature accepts an audio event, such as an ADA
message's `mAudioEvent`. Importing an event does not play it or create a message trigger.

## Declare sounds

Place the audio file inside the directory containing your `pack.yml`:

```text
DataForge/
  pack.yml                  # ref: MyPack
  welcome.sound.yml
  audio/
    welcome.flac
```

```yaml
# file: welcome.sound.yml
type: sound
sounds:
  - id: AdaWelcome
    file: audio/welcome.flac
    name: Welcome voice line
    description: Volume of the ADA welcome message
    category: Voice
    subCategory: ADA
```

`sounds:` must contain at least one entry. Every entry requires `id` and `file`;
the four display fields are optional and must be non-empty strings when supplied.

| Field | Meaning |
| --- | --- |
| `id` | Stable event id. Start with an ASCII letter; remaining characters may be ASCII letters, digits, `_`, `.`, or `-`. |
| `file` | WAV or FLAC path relative to the pack root, not the YAML file's directory. |
| `name` | Sound setting label; defaults to `<id> volume`. Unused for ADA's shared native control. |
| `description` | Sound setting help text; defaults to an explanation of playback volume. Unused for ADA's shared native control. |
| `category` | Group label below the native Audio settings section. |
| `subCategory` | Additional Audio group label. `ADA` selects the game's native Dialogue Volume instead of a separate sound slider. |

Set `subCategory: ADA` on every ADA sound, as in the example above. This value is
case-insensitive and trims surrounding whitespace. These events route through
Satisfactory's native VO audio bus and use **Options → Audio → Dialogue Volume**,
including changes made during playback. They do not create individual KDataForge
volume sliders or a separate ADA volume control. Their `category`, `name` and
`description` remain accepted metadata but do not create an Audio row.

Other sounds keep their individual volume sliders, defaulting to 100%, where 0%
mutes them. Their `category` and `subCategory` combine into one Audio subcategory;
without either field, it is `KDataForge sound events`. These events route to the
master audio bus. All volume controls appear only under **Options → Audio**,
never in KDataForge pack configuration. Audio preferences are local to each
player and are not synchronized by the host. There is no `volume` field.

Existing individual ADA preferences are removed during Audio settings synchronization
once an entry uses `subCategory: ADA`; stale per-message menu registrations are
removed too. The existing native Dialogue Volume becomes authoritative. Other sounds'
local Audio preferences retain their values. Older `__sounds.*.volume` entries
in pack configuration files no longer affect playback; they can be removed.

## Accepted audio

- Little-endian RIFF/WAVE containing uncompressed 16-bit PCM, or native lossless FLAC containing 16-bit PCM.
- Mono or stereo, with a sample rate from 8,000 through 192,000 Hz.
- A non-empty audio payload containing complete PCM frames; maximum 64 MiB for both the encoded file and decoded PCM.
- A `.wav` or `.flac` extension, matched without regard to case.
- FLAC must declare its nonzero total frame count in STREAMINFO. Decoding verifies the declared frame count and PCM MD5 when supplied.

MP3, OGG (including Ogg FLAC), 24-bit FLAC and floating-point WAV are unsupported. Export
as PCM16 WAV or native 16-bit FLAC in your audio editor. Files and any symbolic links must resolve inside
the pack directory; absolute paths and paths escaping the pack are rejected.

Existing WAV packs continue to work. To reduce download size without changing audio,
convert PCM16 WAV to FLAC without resampling, mixing channels or changing bit depth,
then update only `sounds[].file`. Keep the sound ID and message references unchanged.
FLAC is decoded to the same PCM for playback, so runtime audio memory does not shrink.
FLAC packs require a KDataForge build with FLAC support; keep WAV when supporting
older builds. The editor checks FLAC structure and format limits; the game importer
also decodes frames and verifies the supplied PCM checksum.

Generated events play once in 2D and route to the master bus, or the native VO bus
for `subCategory: ADA`. This document type
does not author loops or spatial attenuation.

## Reference an event

Inside the same pack, use the bare event id in an audio event property:

```yaml
type: dataasset
assets:
  - id: WelcomeMessage
    class: /Script/FactoryGame.FGMessage
    properties:
      - path: mAudioEvent
        value: AdaWelcome
```

This creates a message asset with an audio reference. A separate game or mod
workflow must trigger that message.

The full event object path for `ref: MyPack` is:

```text
/KDataForge/GenAssets/MyPack.Gen_MyPack_AdaWelcome
```

Use the full path when referring to the event from another pack. Audio events are
assets, so their paths have no `_C` suffix. Sound ids share the generated asset
namespace with images, curves and data assets; choose distinct ids across those
types. See [Generated Content Short Ids](/kdataforge/reference/yaml-schema#generated-content-short-ids)
for reference resolution.

## Load stage and multiplayer

Sounds run in the `Assets` stage, before `dataasset` documents resolve properties
such as `FGMessage.mAudioEvent`, and before later CDO changes. File ordering does
not require placing a sound YAML before a data asset YAML.

Install the same pack definitions on every multiplayer client and the server.
Every client, including a listen-server host, also needs the referenced audio files.
Dedicated servers do not need WAV or FLAC files: they validate the relative path syntax
and create placeholder events at the same generated asset paths, without opening
audio files, creating bank caches or loading Wwise banks. Messages, subtitles and
server-side triggers remain available. Audio contents and symbolic-link containment
are checked on clients, where the audio files exist. Importing on the server does
not transfer audio files to clients.

The workspace's Alpakit `PackagePlugin` automatically excludes raw `.wav` and `.flac` files
from dedicated-server staging for WindowsServer and LinuxServer. This also applies
to the server directories inside merged bundles and direct server deployments;
the Windows client directory retains its audio. No YAML conditions or extra
pack settings are needed. Keep the sound YAML and its message references in server
packages. When packaging with an older Alpakit, audio files can remain in server
packages harmlessly; older KDataForge versions still require them during import.

An Alpakit filter that excludes only `.wav` keeps `.flac` files in dedicated-server
packages. Extend that filter to both formats to obtain the same server size savings;
keep client audio and server YAML definitions.

## Troubleshooting

- **File cannot resolve:** Check the path relative to `pack.yml`, filename case on
  Linux, and whether a symbolic link points outside the pack.
- **WAV rejected:** Re-export as uncompressed PCM16 mono/stereo WAV within the rate
  and size limits above. Renaming an MP3 to `.wav` does not convert it.
- **FLAC rejected:** Export native 16-bit FLAC with a known frame count, within both size limits. Re-export files with checksum failures; renaming another format does not convert it.
- **Generated event missing:** Check for duplicate ids, including collisions with
  other generated assets, and confirm the sound document's conditions pass.
- **Bank cache cannot be written:** The client must be able to write generated
  banks under `FactoryGame/Content/KDataForgeRuntimeSounds/`.
- **Wwise rejects the bank:** Inspect `LogAkAudio` and `LogWwiseFileHandler` alongside
  KDataForge diagnostics.
- **Import succeeds but nothing plays:** Confirm a consumer triggers the event and
  check the sound's volume setting and the game's master volume.
