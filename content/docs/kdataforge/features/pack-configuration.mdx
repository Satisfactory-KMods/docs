A `*.config.yml` or `*.config.yaml` file defines settings offered by a pack. Use
`type: config` and a non-empty `fields` list. Definitions load separately from the
player's values, stored under `FactoryGame/Configs/Packs/<PackRef>.config.yml`.
Keep the pack's `ref` stable; packs defining configuration need a ref of at most
50 characters.

## Removing obsolete configuration

After a successful definition load, KDataForge rewrites the pack's values file
using its current fields. Values of remaining fields are retained; removed fields
and their empty groups disappear, including legacy `__sounds` entries. Renaming a
field creates a new key and removes the old key; migrate any values you need before
renaming it.

Generated `FactoryGame/Configs/Packs/<PackRef>.config.yml` files are removed when
their pack is no longer installed or no longer defines configuration. This happens
after pack discovery and definition processing, including on reload. Installed
packs that are disabled or skipped because of dependencies remain known and keep
their files. Configuration documents skipped by conditions retain their stored
keys rather than being mistaken for removed fields.

Deletion only targets direct `*.config.yml` files carrying the generated
`# KDataForge pack configuration` header and containing valid YAML mappings.
Unmarked or unreadable files are left untouched. Discovery warnings or errors
prevent file deletion for that load. Invalid or partially skipped definitions
prevent obsolete-field pruning for their pack. Read-only editor registries never
write or delete values files. Host-replicated values do not trigger local cleanup.

```yaml
# file: balance.config.yml
type: config
category: /Script/FactoryGame.FGCategory
fields:
  - id: balance.duration
    type: number
    valueType: float
    name: Production duration
    description: Recipe duration in seconds used by this pack's patches.
    default: 1
    min: 0.25
    max: 4
    step: 0.25
    display: slider
    apply: hot
```

The category above uses the base category. For a named settings section, use a
category subclass as described below. A field with an error is skipped while
other valid fields can still load. Static document `conditions` are supported;
configuration definitions cannot depend on `config:` conditions themselves.

## Blueprint pack lists

For settings widgets, `Get All Pack Infos` returns only packs with at least one
authored configuration field. Sound-volume controls belong only to the local
Audio settings and do not make a pack appear in this list.
Packs with no valid fields are omitted. Active packs appear in load order,
with the first loaded pack first. Dependencies load before their dependents;
among packs ready to load, higher priority comes first, then `ref` alphabetically.
Inactive packs follow the active entries, sorted by `ref`. Filter on `mState`
when the widget should display only active packs, and keep the returned array
order rather than sorting it again.

`Get Pack Info(PackRef)` can still look up a specific pack without configuration fields.

## Ready-made Blueprint settings widgets

KDataForge's runtime UI module provides native C++ widgets using FactoryGame's
options-row, checkbox, slider,
dropdown, font and status-icon assets.

Rows keep the original 300-pixel control column. Checkbox and slider rows use
the 33-pixel baseline; text and number inputs use 40 pixels. Text inputs use
FactoryGame's dark input background, left-aligned font and orange hover/focus
border. Apply, Discard, Add and Remove use FactoryGame's standard buttons,
including their native interaction states. Reset retains the compact options icon.
Multiline text, tags and collections expand vertically. Use an automatically
sized panel slot; a fixed 33-pixel slot would clip these controls.

The released `2026.4.582` settings page requires KUI. The upcoming development release moves the
category, empty-state, and styled tooltip visuals into KDataForge itself and removes that runtime
KUI requirement.

In a Widget Blueprint:

```text
Get Config Descriptions Flat (PackRef)
  → For Each
  → Create Config Widget (Description = Array Element)
  → Add Child to your panel
```

`Create Config Widget` automatically chooses the matching class. You can also use
`Create Widget` with a specific class and connect its exposed **Description** pin:

| Description kind | Widget class |
| --- | --- |
| Text, including multiline text | `KDFConfigTextWidget` |
| Gameplay tag | `KDFConfigTagWidget` |
| Number input | `KDFConfigNumberWidget` |
| Slider | `KDFConfigSliderWidget` |
| Boolean | `KDFConfigBooleanWidget` |
| Select | `KDFConfigSelectWidget` |
| Multi-select | `KDFConfigMultiSelectWidget` |
| Text, number or tag list | `KDFConfigListWidget` |

The row manages its label, tooltip, current value, validation errors, default reset,
pending-change indicator and restart notices. Multiplayer clients without edit
permission see disabled controls. Tags offer registered-tag suggestions and an
editable path; lists support adding, removing and editing entries within their
configured limits.

Edits remain pending. **Reset to default** also creates a pending change.
**Apply pack changes** saves all pending edits of the description's pack;
**Discard pack changes** discards that pack's pending edits. These actions include
edits in sibling rows. Hot settings follow the normal KDataForge reload rules;
cold settings show the restart requirement. Dedicated-server admin requests keep
the pack's controls disabled until all request chunks finish, including errors
and timeouts.

For a menu with one shared footer, pass **Show Apply Discard = false**, or call
`Set Show Actions(false)` on its rows. Connect the menu's buttons to
`Apply Changes` and `Discard Changes` on any row belonging to that pack. The
widget checks validation errors in the pack's other visible rows before applying.
Calling the lower-level `Apply Config Changes(PackRef)` directly does not inspect
unfinished widget input.

For a shared Reset All button, call `Reset Pack Config To Default(PackRef)`.
It stages each editable field's default without saving or reloading. Pass an
empty `PackRef` to reset all packs. Read-only fields remain unchanged; an unknown
pack or unavailable subsystem does nothing. Apply or discard the staged reset
through the same menu actions as other pending edits.

Use the pure Blueprint node `Is Pack Config Dirty(PackRef)` to enable a shared
Apply button. It returns whether that pack has unsaved pending values; an empty
`PackRef` checks all packs. An unknown pack or unavailable subsystem returns false.
`Has Pending Config Changes` remains available with the same behavior.

For updates without polling, call `Get KDataForge Subsystem` and bind to
`On Pack Config Changed`. The event supplies `Pack Ref` and `Is Dirty`; filter
the reference for the pack displayed by your menu. It fires on configuration
value or state changes, including edits, reset, apply, discard and reload, even
when the dirty flag stays unchanged. Deferred load events are grouped per pack.
After binding, read `Is Pack Config Dirty` once to initialize the button.
Unbind your listener when the menu closes. For a menu spanning all packs, query
`Is Pack Config Dirty` with an empty reference after each event.

The row also exposes `Apply Changes`, `Discard Changes`, `Reset to Default`,
`Get Validation Error` and `On Applied`. `On Applied` reports the initial pending
result for an admin request, then the combined result after every chunk completes.
Keep the row's `Description` reference instead of copying configuration values
into unrelated widget variables.

Reloads refresh labels, constraints and values. Removed fields disable their rows.
If an author changes a field's kind during development, rebuild the menu with
`Create Config Widget` to obtain the new matching widget class.

### Preview in the Unreal Editor

With the KDataForge UI module loaded, use the editor console to preview config
definitions from a pack directory without starting PIE or writing saved values:

```text
KDF.Config.PreviewWidgets "C:/MyMod/DataForge"
```

The preview allows pending-value edits and resets, but omits Apply/Discard because
it does not represent a running pack. Actual saving, hot reload and multiplayer
permissions must be checked in a game session.

## Field types at a glance

| `type` | `valueType` choices | Default `valueType` | Shape |
| --- | --- | --- | --- |
| `text` | `string`, `text`, `name`, `tag` | `string` | String, or string list with `multiple: true` |
| `number` | `int8`, `int16`, `int32`, `int64`, `uint8`, `float`, `double` | `int32` | Number, or number list with `multiple: true` |
| `boolean` | `bool`, `uint8` | `bool` | Boolean; `multiple` is not supported |
| `select` | All text and number types above, plus `bool` | `string` | One option value, or list with `multiple: true` |

## Common field keys

Every field requires `id`, `type`, `name`, `description` and `default`.

| Key | Meaning |
| --- | --- |
| `id` | Stable dotted identifier, such as `balance.duration`; used to read the value. |
| `type` | Control family from the table above. |
| `valueType` | Stored element type; defaults depend on `type`. |
| `name`, `description` | Non-empty display text, either a string or keyed localized text. |
| `default` | Initial value satisfying the field's type and constraints; a list when `multiple: true`. |
| `tooltip` | Optional map containing `title`, `text`, or both; each accepts localized text. |
| `category` | Category class for this field; overrides the document category. Required at one of these levels. |
| `apply` | `cold` by default, or `hot`; see application rules below. |
| `order` | Integer sort position within its category; otherwise declaration order across config files sorted by path. |
| `multiple` | Enables lists for `text` and `number`, or multi-selection for `select`; defaults to `false`. |

Identifiers use ASCII segments matching `[A-Za-z_][A-Za-z0-9_]*`, separated by
dots, and may contain at most 200 characters. They must be unique across the
pack's config files, ignoring case. An id cannot also be the dotted prefix of
another id: do not define both `balance` and `balance.duration`. The identifiers
`true`, `false`, `in` and `contains` are reserved; the `__sounds` namespace is
reserved for compatibility with older sound controls. Dotted ids become nested maps in the
saved values file.

`descriptionClass` and field-level `properties` are reserved. The schema accepts
them, but the runtime ignores them and reports a warning. They do not create
custom controls or patch game properties.

## Categories

Set `category` on the document as the default, or on individual fields. It must
resolve to a `UFGCategory` subclass. Accepted forms include a class path, a bare
id of a class generated in the same pack, or its full generated path:
`/KDataForge/Gen/<PackRef>.Gen_<PackRef>_<Id>`.

Settings sections sort by the category's `mMenuPriority`. An unresolved or
incorrect class produces an error and falls back to the base `UFGCategory`
bucket. Create category subclasses with [Type: class](/kdataforge/features/custom-classes).

## Numbers

| Key | Constraint or behavior |
| --- | --- |
| `min`, `max` | Optional inclusive bounds; `min` cannot exceed `max`. Values outside these bounds are clamped. |
| `step` | Positive control increment; a whole number for integer types. |
| `decimals` | Fractional digits shown and stored, from 0 to 9. Otherwise inferred from `step`, or defaults to 4 for `float` and 6 for `double`. |
| `display` | `slider` or `input`. An explicit slider requires `min < max` and cannot use `multiple: true`. |

Without `display`, a scalar field with both bounds and `min < max` becomes a
slider; other number fields use an input. Integer types require integer defaults,
bounds and steps. For lists, numeric constraints apply to each element.

## Text, tags and selections

Text fields accept `maxLength` from 1 to 1024, defaulting to 1024. Use
`multiline: true` only with `type: text` and `valueType: text`. With
`valueType: tag`, `tagRoot` restricts values to that gameplay-tag root; tags need
not already be registered when configuration is read.

Text and number lists use `minCount` and `maxCount`; lists hold at most 64
elements, with `maxCount` defaulting to 64. These count keys require
`multiple: true`.

Select fields require a non-empty `options` list. Each option has a unique
`value` matching the field's `valueType` and a display `label`. The default must
be one of those values, or a list of option values for a multi-select. Text
option values are case-sensitive.

```yaml
type: config
category: /Script/FactoryGame.FGCategory
fields:
  - id: features.mode
    type: select
    name: Feature mode
    description: Choose which variant the pack uses.
    default: standard
    options:
      - { value: standard, label: Standard }
      - { value: extended, label: Extended }
```

Multi-selects use `minSelected` and `maxSelected` instead of the list count keys.
The minimum cannot exceed the number of options, and the maximum cannot be below
the minimum or exceed 64.

## Reading values

Other documents can read a typed value with `cfg:<id>`, or
`cfg:<PackRef>:<id>` to name another pack explicitly. String templates support
`{cfg:<id>}` substitutions, and `config:` conditions can use configuration
expressions. Configuration definitions themselves cannot use those conditions.

For example, a property operation can consume the slider above directly:

```yaml
# Inside a patch's properties list:
- path: mManufacturingDuration
  value: cfg:balance.duration
```

This assigns the configured number to the recipe's duration property.

## Hot and cold values

`apply: cold` is the default. Applying a changed value saves it, but running
content keeps the value used during its initial load. The runtime reports that
a restart is required.

`apply: hot` saves changes and triggers a KDataForge content reload when hot
values change. The reload can update consumers during the current session.
Whether the game actually uses a changed property immediately depends on that
property and its consuming system. A hot field used in a cold context or cold
property is flagged with a restart recommendation.

## Cold properties

Configuration application mode and property reload classification are separate.
Reflection exports classify class properties as `hot`, `cold` or `newActors`:

- `hot`: explicitly classified as applying live.
- `cold`: read once or during object creation; changing it does not refresh existing state.
- `newActors`: class-default changes affect newly spawned actors or components;
  a patch can use `applyToSpawnedActors: true` to include existing actors.

The editor reports cold and `newActors` operations as `property.cold`. Catalog
entries marked `verified: false` remain assumptions awaiting game verification.
See [Reflection Export](/kdataforge/reference/reflection-export#reload-classification-and-cold-property-catalog)
for the `kdf.reload`, `kdf.reloadReason` and cold-property catalog fields.

## Localized names

Field names, descriptions, tooltip titles and texts, and select labels accept
the keyed text form:

```yaml
name:
  key: Config_Speed_Name
  ns: MyPack
  source: Production duration
```

Provide translations through [Type: localization](/kdataforge/features/localization)
using the same namespace and key. When overriding existing source text, preserve
the exact source string required by Unreal's source-hash matching. These display
texts do not change field ids or stored option values.

## Pack name, description and icon

`pack.yml` supplies the pack's display `name`, `description` and optional `icon`.
The runtime falls back to the pack ref when the name is absent; the editor schema
requires a name. The description accepts either a string or keyed localized text.

An icon can be a `UTexture2D` object path beginning with `/`, or a pack-relative
`png`, `jpg`, `jpeg`, `tga` or `bmp` file. Relative files must remain inside the
pack folder. Image-file limits are 16 MB and 4096 × 4096 pixels. Dedicated servers
skip icon loading.
