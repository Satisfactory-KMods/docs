KDataForgeJS runs typed scripts inside a KDataForge pack. Use it when a change needs computed values, hooks, delegates,
timers, or runtime decisions. YAML remains the shorter option for static content and property patches.

Scripts use KDataForge's catalog, transactions, authority checks, reload baselines, and limits. Unreal objects stay
behind typed handles.

## Start a project

```bash
npx @sf-kmods/kdataforgejs-cli init MyPack
cd MyPack
npm install
npx @sf-kmods/kdataforgejs-cli game-data
npm run verify
```

The project keeps npm tooling outside its `DataForge/` pack. The game provides `@sf-kmods/kdataforgejs` at runtime and
does not load `node_modules`.

A minimal entry contains one default handler:

```ts
import { defineHandler } from "@sf-kmods/kdataforgejs";

export default defineHandler(async (ctx) => {
  console.info("loaded", ctx.catalog().digest);
});
```

KDataForge derives the script identity from the pack ref and `scripts/main.ts`. `meta` is optional and requests extra
capabilities only when the script needs them.

[Set up a KDataForgeJS project](/kdataforge/features/kdataforgejs/project-setup) covers project layout, game-data import,
generated types, capabilities, supported imports, and every CLI check.

## Use generated game APIs

The generated `satisfactory` module contains class symbols from the active reflection export:

```ts
import { FGItemDescriptor } from "satisfactory";

const itemClass = ctx.getClass(
  FGItemDescriptor,
  "/Script/FactoryGame.FGItemDescriptor",
  { checked: true },
);

const cdo = itemClass.getClassDefaultObject();
console.info(cdo.mDisplayName.get());
console.info(FGItemDescriptor.GetItemName(itemClass));
```

Properties, functions, enums, structs, hooks, and delegates carry generated types. Setters record reload baselines.
Class, object, and data-asset lookups return opaque handles with catalog, realm, world, and generation checks.

[Use reflected game APIs](/kdataforge/features/kdataforgejs/reflection) covers class search, checked lookups, CDOs,
property proxies, casts, native functions, and non-reflected C++ members.

## React to the game

Generated hooks attach directly to class symbols:

```ts
import { BP_WaterTurbineNode } from "satisfactory";

ctx.hook(
  BP_WaterTurbineNode,
  BP_WaterTurbineNode.hooks.ReceiveBeginPlay,
  "after",
  ({ target }) => {
    if (target === undefined) return;
    target.mNodeSlowPowerOutput.set(60);
  },
);
```

Events, hooks, delegates, ticks, and timers belong to their script realm. Reload, pack disable, world travel, and realm
shutdown revoke them automatically. Manual unsubscribe methods remain available for early shutdown.

[Hooks and lifecycle](/kdataforge/features/kdataforgejs/hooks-and-lifecycle) explains callback types, hook phases,
delegates, timers, cleanup bags, and `/kdf reload`.

## Create content

Scripts can import verified pack files and call typed KDataForge handlers:

```ts
import { FGItemDescriptor } from "satisfactory";

const item = ctx.createItem({
  id: "my-pack.rare-part",
  parent: FGItemDescriptor,
  displayName: { namespace: "my-pack", key: "rare-part", source: "Rare Part" },
  form: "solid",
  stackSize: "medium",
});
```

`ctx.applyDocument` uses the same documents as YAML. Typed helpers cover items, recipes, and dynamic classes. KDataForge
validates each change before commit and owns rollback.

[Create content from TypeScript](/kdataforge/features/kdataforgejs/content-authoring) covers file imports, document
application, item and recipe helpers, dynamic classes, initialization, and authority.

## Know the runtime boundary

The runtime includes ECMAScript collections, typed arrays, promises, regular expressions, Base64, URI encoding, and
microtasks. Context utilities add hashes, UUIDs, realm-owned timers, and native cleanup bags. The built-in module adds
[144 typed helper functions](/kdataforge/features/kdataforgejs/helpers) for common collection and transformation work.

Node.js, npm packages, unrestricted files, network access, and browser APIs are absent. KDataForge checks capabilities,
authority, lifecycle, handles, deadlines, and quotas at native boundaries.

[Runtime APIs and limits](/kdataforge/features/kdataforgejs/runtime) lists available built-ins, deterministic patterns,
logging, missing APIs, and runtime checks.
