This document type runs in the `SubsystemMods` stage, after all content-generation stages. A session
restart is required to pick up changes. Its entries key is `entries`, and the `track:` field accepts
`Default` or `Exploration`, defaulting to `Default`.

This one's simple in shape but strict about timing: it sets how many AWESOME Sink points an item is
worth.

```yaml
type: sinkpoints
track: Default # or Exploration
entries:
  - item: /KDataForge/Gen/MyPack.Gen_MyPack_MySuperIngot
    points: 8
  - item: /Game/FactoryGame/Resource/Parts/IronIngot/Desc_IronIngot.Desc_IronIngot_C
    points: 100
    overridden: 50 # optional — a separate "overridden" point value some UI paths read
```

- `item:` must resolve to an `UFGItemDescriptor` subclass — both the bare generated-content id
  shortcut (e.g. `item: MySuperIngot` instead of the full `/KDataForge/Gen/...` path — see
  [Generated Content Short Ids](/kdataforge/reference/yaml-schema#generated-content-short-ids))
  and the bare class-name shortcut work here too (see
  [Targeting → bare class name](/kdataforge/features/targeting#target--bare-class-name--shortcut-for-the-full-class-path)),
  though sticking to full paths in a published pack is still the safer habit.
- `points:` is a plain integer. `overridden:` is optional, and it's only needed if you specifically
  want a distinct "overridden" points value separate from the base one.
- One `sinkpoints` document builds one `UDataTable` and registers it against whichever `track:` you
  picked. Multiple documents, even across packs, just add more rows to the sink subsystem: they
  don't need to be merged into one file.

## Registration timing and Resource Node boundary

KDataForge queues sink point tables during initialization and registers them per world before SML's
content registry freezes. YAML is scanned once per GameInstance, so changes require a session
restart. The runtime exposes no live YAML rescan command.

Sink points only control item scoring in the AWESOME Sink. They do not place Resource Nodes, change
purity, or grant scanner visibility. See
[Resources and Resource Nodes](/kdataforge/features/resources) for those systems.

## Troubleshooting

- **Changed points do not appear**: restart the session or dedicated server.
- **Points show as 0, or unchanged in-game**: check that `item:` actually resolved (`/kdf report`
  lists a failed patch if the class path was wrong), and make sure you're looking at the right
  `track:` (`Default` vs. `Exploration` are separate tables).
- Sink points for a freshly generated item are part of the combined pack in
  [End-to-End Pack](/kdataforge/examples/end-to-end-pack).
- **A resource still has no mineable node or scanner entry:** Sink scoring is unrelated. Follow the
  descriptor, world-node, and scanner steps on the Resources page.
