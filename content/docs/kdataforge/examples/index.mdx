These examples show several document types working together in complete packs. They assume a pack
root at `<your-mod>/DataForge/` and some familiarity with
[property types](/kdataforge/features/property-types),
[operations](/kdataforge/features/operations), [targeting](/kdataforge/features/targeting), and
[pack conditions](/kdataforge/features/conditions-and-packs).

If you are learning the workflow, begin with [Create your first pack](/kdataforge/getting-started).
Use the [How-to guides](/kdataforge/tutorials) for a guided task and
[Reference](/kdataforge/reference) for exact field definitions.

For maintained packs used in a public mod, browse
[KPatchwork's `DataForge` directory](https://github.com/Satisfactory-KMods/KPatchwork/tree/main/DataForge).
Each subdirectory is a real compatibility pack with its own `pack.yml` and focused YAML documents.
These packs are useful examples for conditions, cross-mod targets, dependencies, and repository
layout. They also follow KPatchwork's extra contribution policy, so fields such as `contributer`
are repository requirements rather than KDataForge runtime requirements.

## Edit existing content

- [Balancing](/kdataforge/examples/balancing) patches existing recipes, items, resources,
  equipment, consumables, radioactivity, belt speed, schematics, milestones, research trees,
  vehicles, trains, creatures, categories, and tag-selected targets. It uses `type: cdo` throughout
  and generates no classes.
- [Power and machines](/kdataforge/examples/power-and-machines) changes power consumption,
  manufacturing speed, generator output, extractor cycle time, pipeline flow limits, power-storage
  capacity, and drone-station logistics. Its runtime actor patches also affect placed buildings.

## Create connected content

- [A complete building](/kdataforge/examples/building-chain) follows the dependency chain from a
  generated buildable class through its descriptor, build recipe, production recipes, schematic,
  and sink points. Six files reference the class generated by the preceding file.
- [End-to-end pack](/kdataforge/examples/end-to-end-pack) combines an item, recipe, schematic with
  an inline unlock, sink points, German localization, a KAPI data asset, and a patch for another
  mod's data assets. It also preserves a shipped generated id with `redirects:`.
- [KAPI data assets](/kdataforge/examples/kapi-data-assets) creates every KAPI
  `PrimaryDataAsset` family supported by the example set: air collector, cleaner, modular miner,
  slug breeding, and extractor or resource allow-lists.

## Build progression data

- [Delivery task trees](/kdataforge/examples/delivery-task) creates a complete
  `UKAPIDeliveryTask` graph with five nodes, negative coordinates, multi-flag `mParentTask` values,
  repeated-parent thresholds, Endless fields, and a forced schematic unlock.
- [Removed repeat-purchase unlocks](/kdataforge/examples/repeat-purchase-schematic) explains how to
  migrate an older KLib repeat-purchase reward pack to Delivery tasks.
- [Unlock catalogs](/kdataforge/examples/unlocks-catalog) points to the current base-game and mod
  unlock references and explains which one to use.

For every base-game `FGUnlock` subclass, its properties, and its instantiation constraints, use
[Base-game unlock classes](/kdataforge/reference/base-game-unlock-classes).
