These `type: dataasset` examples create new instances for every KAPI data asset type. To edit
*existing* instances through `type: cdo`, see
[Data Assets](/kdataforge/features/data-assets). Four of the five examples below use real property
values from actual shipped Satisfactory Plus / KLib content, so the numbers are realistic, not
placeholders. The fifth (extractor/resource allow-lists) is illustrative since no shipped instance
of that type exists to read from.

## UKAPIAirCollectorData: air collector production

Each Air Collector resource is its own `UKAPIAirCollectorData` instance the DataAsset registers a
new gas/resource the Air Collector can extract, it does not patch an existing one. See the
[full property reference](/satisfactory-plus/kdataforge/air-collector/) for every field; the example
below mirrors Satisfactory Plus's own shipped "Air Collector extract Toxic Air via Resource Nodes"
asset. Note `bUseHightBasesdProduction` selects one of two mutually exclusive production models.
here it's `false`, so `mMaxHit`/`mProductionPerHit` are the active fields and
`mProduceItemCountMin`/`Max`/`Base` (the other model) are omitted entirely, not just left at
defaults.

```yaml
# file: air-collector-toxic-air.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: AirCollector_ToxicAirNode
    class: /Script/KAPI.KAPIAirCollectorData
    properties:
      mRecipePrio: 100
      mRangeToScan: 2500
      bCheckNodes: true
      mTraceChannel:
        - ObjectTypeQuery1
        - ObjectTypeQuery2
        - ObjectTypeQuery9
        - ObjectTypeQuery6
      mItemClass: /KLib/Assets/Ressources/Raw/Gas/Desc_ToxicAir.Desc_ToxicAir_C
      mProductionTime: 6
      bUseHightBasesdProduction: false
      mMaxHit: 2
      mProductionPerHit: 6000
```

## `UKAPICleanerItemDescription`: Filtrator (Cleaner) recipes

A `dataasset` document targeting `KAPICleanerItemDescription` creates a brand-new Filtrator recipe: which input fluid it
consumes, what it outputs, and any bonus items produced alongside the main conversion. See the
[full property reference](/satisfactory-plus/kdataforge/filtrator/) for every field, including `FKAPICleanerInfo`. The
example below reproduces Satisfactory Plus's own "Filtrator filter Wastewater" recipe: 6000 wastewater in, 4000 clean
water out over 6 seconds, plus two bypass products (crushed zinc and crushed caterium) that come out independent of the
main fluid conversion. `mCleanerItemInfo` is left out entirely here, it's optional, and this real recipe ships with no
extra cleaner item required (`mCleanerItemInfo.mProduceItem` is `None` in the shipped asset).

```yaml
# file: filtrator-wastewater.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: CleanerItem_WasteWater
    class: /Script/KAPI.KAPICleanerItemDescription
    properties:
      bSkipUnlockCheck: false
      mProductionTime: 6
      mInFluid:
        ItemClass: /KLib/Assets/Ressources/Raw/Fluids/Desc_Wastewater.Desc_Wastewater_C
        Amount: 6000
      mOutFluid:
        ItemClass: /Game/FactoryGame/Resource/RawResources/Water/Desc_Water.Desc_Water_C
        Amount: 4000
      mBypassProducts:
        - mProduceItem: /KLib/Assets/Parts/Production/Crushed/Desc_CrushedZinc.Desc_CrushedZinc_C
          mProductionTime: 12
          mProduceAmount: 6
        - mProduceItem: /KLib/Assets/Parts/Production/Crushed/Desc_CrushedCaterium.Desc_CrushedCaterium_C
          mProductionTime: 12
          mProduceAmount: 6
```

## UKAPIModularMinerDescription: modular miner ore entries

Full [property reference](/satisfactory-plus/kdataforge/modular-miner/). Each `UKAPIModularMinerDescription` instance
registers one raw-resource entry the KAPI modular miner can extract, its rarity/found flavor text, node screenshot,
which attachment modules are required or blocked, and the minimum drill tier needed. The example below mirrors a real
shipped Cryolite raw-ore entry:

```yaml
# file: modular-miner-cryolite.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: MM_Cryolite
    class: /Script/KAPI.KAPIModularMinerDescription
    properties:
      mRarityText: 'Common'
      mFoundText: 'Can be found in every biome.'
      mNodeScreenshot: /SatisfactoryPlus/AssetDatas/Miner/UI/TXUI_Wiki_ResourceNode_Cryolite.TXUI_Wiki_ResourceNode_Cryolite
      mIsFallbackDescriptor: false
      mNeededModules:
        - /KAPI/Attachments/ModularMiner/Attachment_MM_MiningHead.Attachment_MM_MiningHead_C
      mPreventModules:
        - /KLib/Assets/Buildings/ModularExtractor/Modules/Smelter/Build_SmelterModule.Build_SmelterModule_C
      mResourceClass: /Game/FactoryGame/Resource/RawResources/RawQuartz/Desc_RawQuartz.Desc_RawQuartz_C
      mDrillTier: 1
```

`mFluidInfo` and `mModuleInformation` are optional `TMap` fields (keyed by an item class and a waste-producer module
class respectively) for entries that feed fluid or waste-producer modules, see the property reference for their
map-key/value shapes. A resource entry that doesn't use either module type, like this one, works fine without them.
`mScannerTier` is unused and left out entirely.

## UKAPISugHatchingData: slug breeding & incubation

Defines a slug species end to end: what it hatches from, how the incubator raises it, and its
breeding-cycle behavior. See the [full property reference](/satisfactory-plus/kdataforge/slug-breeding/)
for every field, including the fluid-incubator properties (`mTankTier`, `mFluidConsume`,
`mFluidClass`, `mFluidConsumeTime`) left out below since `bRequireFluid` is `false` here. The
example reproduces the shipped Red Slug breeder, trimmed to two `mPossibleSlugs` entries for
readability.

```yaml
# file: kapi-slug-red.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: RedSlugBreeder
    class: /Script/KAPI.KAPISugHatchingData
    properties:
      mSlug: /KLib/Assets/Buildings/SlugHatching/Desc/Slugs/SlugDesc_Red.SlugDesc_Red_C
      mEgg: /KLib/Assets/Buildings/SlugHatching/Desc/Eggs/EggDesc_Red.EggDesc_Red_C
      mEggColor:
        R: 1
        G: 1
        B: 1
        A: 1
      mSlugTier: -1
      mHatchDuration: 10
      mPowerConsume: 0.1
      mIncubatorTier: 1
      bRequireFluid: false
      mPossibleSlugs:
        - mSlug: /KLib/Assets/Buildings/SlugHatching/Desc/Slugs/SlugDesc_Red.SlugDesc_Red_C
          mProductionCount: 1
          mProbability: 100
          mFixedChanceMultiplier: 0.1
          bShouldUseFixedChance: true
        - mSlug: /KLib/Assets/Buildings/SlugHatching/Desc/Slugs/SlugDesc_Orange.SlugDesc_Orange_C
          mProductionCount: 1
          mProbability: 0.38
          mFixedChanceMultiplier: 1
          bShouldUseFixedChance: true
      mProductionCountEggs: 1
      mBreedingTime: 40
      mDieTime: 100
      mRequiredFood: /KLib/Assets/Parts/Production/Food/Desc_SnailFood_Tier_20.Desc_SnailFood_Tier_20_C
      mFoodConsumePerCycle: 2
      mFoodDuration: 20
      mComfortableWith:
        - /KLib/Assets/Buildings/SlugHatching/Desc/Slugs/SlugDesc_Orange.SlugDesc_Orange_C
      mMinHumidity: 0.8
      mMaxHumidity: 0.85
      mMinHeat: 80
      mMaxHeat: 100
      mDayTime: Any # EKAPISlugTime enum name (Any/Day/Night), not a raw number; Any is also the default
```

## UKAPIExtractorAllowList: Registering new Extractors and Resources

Unlike the other examples on this page, no shipped instance of this asset exists to read from the
wiki data export has zero `UKAPIExtractorAllowList` entries. SF+ ships its own default allow-list
as an existing default asset that mods normally `type: cdo` patch instead (see
[Data Assets](/kdataforge/features/data-assets)); creating a brand new instance from scratch, as
below, is mainly useful for a self-contained mod that wants its own allow-list rather than editing
SF+'s. The values below are illustrative adjust the class paths to your own mod's classes. See
[Extractors → Properties](/satisfactory-plus/kdataforge/extractors/) for the full property reference.

This is the same "hooking up a new resource type" scenario described on that reference page: a new
custom extractor building needs to go in `mAllowedExtractors` before SF+ will treat it as a valid
extractor, and a new resource descriptor needs to go in `mAllowedResources` before any extractor
will recognize it as extractable:

```yaml
# file: my-extractor-allowlist.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: MyModExtractorAllowList
    class: /Script/KAPI.KAPIExtractorAllowList
    properties:
      mAllowedExtractors:
        - /Game/YourMod/Buildable/Build_YourExtractor.Build_YourExtractor_C
      mAllowedResources:
        - /Game/YourMod/Resource/Desc_YourResource.Desc_YourResource_C
    # mDisallowExtractors and mDisallowResources omitted no exclusions.
      mPriority: 0
```

`mPriority` defaults to `0`; raise it only if another mod's allow/disallow list needs to be
overridden for this class (see the priority note on the reference page).

## `UKAPIDeliveryTask`: research-tree / delivery-task nodes

`UKAPIDeliveryTask` places one node on a 2D coordinate grid and links it to a parent node (or
several, at once) via `mParentTask` a **bitmask** property (`EKAPIDeliveryTaskParent`:
`Above`/`Left`/`Right`/`Bottom`/`AboveLeft`/`AboveRight`/`BelowLeft`/`BelowRight`). Like
`UKAPIExtractorAllowList` above, there's no shipped instance to read real values from this
feature isn't part of Satisfactory Plus, it only needs **`KAPI` + `KPrivateCodeLib`** so the
example below is illustrative.

The interesting part is `mParentTask` accepting **more than one flag at once**. Use one scalar name
for one parent or a YAML sequence for several. With `WITH_METADATA`, retained property metadata,
and the enum already loaded, KDataForge resolves and ORs names or `|`-joined strings (`"Above|Left"`).
This enum declares mask values: `Above` (`1`) and `Left` (`2`) combine to `3`. Raw integer masks such
as `3` are accepted by `set` only; `append`/`prepend` and `remove` require named flags. Stripped
metadata or an unresolved enum leaves ordinary integer conversion without named bitmask forms or
mutations. Shipping builds must retain metadata for these named examples. See
[Property Types](/kdataforge/features/property-types#bitmask-integer-properties-with-bitmaskenum-metadata)
for mask-value versus bit-index rules and width limits.

`bRequireAllParents` then switches between AND (`true`, every
flagged parent required; default) and OR (`false`, any one is enough) semantics.
`mRequiredParentCompletions` defaults to `1` and requires that many completed runs from each marked
parent. Values above `1` are intended for branches behind endless tasks and count completed runs,
not queued repeats. See
[Value Forms](/kdataforge/reference/yaml-schema#value-forms-by-property-type) for the full grammar.

Every flag on `mParentTask` must resolve to a real sibling node at the matching coordinate offset
(`Above` → the node directly above, `Left` → directly left, etc.) or the node is rejected at load
time, so a small tree needs coordinates laid out to match:

```yaml
# file: showcase-delivery-task.dataasset.yml
type: dataasset
conditions:
  hasMod: KAPI
assets:
  - id: DeliveryTask_Root
    class: /Script/KAPI.KAPIDeliveryTask
    properties:
      mCoordinate:
        X: 0
        Y: 0
      mName: "Root Task"

  - id: DeliveryTask_Child_Above
    class: /Script/KAPI.KAPIDeliveryTask
    properties:
      mCoordinate:
        X: 0
        Y: 1
      mName: "Single-Parent Child"
      mParentTask: Above
      bRequireAllParents: true

  - id: DeliveryTask_Child_Right
    class: /Script/KAPI.KAPIDeliveryTask
    properties:
      mCoordinate:
        X: 1
        Y: 0
      mName: "Sibling Child"
      mParentTask: Left # points back at (0, 0): the root
      bRequireAllParents: true

  - id: DeliveryTask_Child_AboveAndLeft
    class: /Script/KAPI.KAPIDeliveryTask
    properties:
      mCoordinate:
        X: 1
        Y: 1
      mName: "Two-Parent Child"
    # multiple flags set in parallel
      mParentTask:
        - Above # points to (1, 0)
        - Left # points to (0, 1); both nodes must exist in the tree
      bRequireAllParents: true # AND: both parents must be completed
```

A one-time task (`bIsEndless: false`, the default) can also force-unlock a schematic and grant
rewards on completion, via `mSchematics`/`mRewards`/`mCosts`:

```yaml
- id: DeliveryTask_UnlockSuperIngot
  class: /Script/KAPI.KAPIDeliveryTask
  properties:
    mCoordinate:
      X: 1
      Y: 2
    mName: "Unlock: Pure Super Ingot"
    mParentTask: Above
    bRequireAllParents: true
  # force-unlocked on completion
    mSchematics:
      - /Game/YourMod/Schematics/Schematic_PureSuperIngot.Schematic_PureSuperIngot_C
    mRewards:
      - ItemClass: /Game/FactoryGame/Resource/Parts/IronIngot/Desc_IronIngot.Desc_IronIngot_C
        Amount: 500
    mCosts:
      - ItemClass: /Game/FactoryGame/Resource/Parts/IronPlate/Desc_IronPlate.Desc_IronPlate_C
        Amount: 100
```

The full property set (including the Endless-only fields `mPoolElements`/`mTaskRewards`/`mMaxTasks`/
`mAmountMultiplierCurve`/`mAbsolutMaxItemAmount`) is demonstrated in [KDataForge's own reference
sample pack](/kdataforge/getting-started), `showcase-delivery-task.dataasset.yml`.
